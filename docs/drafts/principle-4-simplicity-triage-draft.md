## 一、用户提供的原始规则（完整留档）

提出的每个方案，应该：
- 判断「该不该做 / 做到什么程度」一律锚目标态，不受现有代码与设计的束缚
- 方案应该尽量简化，以最终目标为准，不追求完美方案，可以考虑牺牲低概率影响小的问题
- 能查的自己查：落笔前先证伪；引用必须真的打开过，不是「我记得它写着」；动一个常量/谓词/字符串前，先 grep 谁在消费它，有什么影响
- 能够自己联网调研的就自己调研：尚在设计中，本地没有相关代码的方案，自己联网找权威最佳实践来调研
- 不确定的方案，先调研再给推荐

不要为一个低概率影响小的问题不断来回纠结完美方案，甚至这个问题可能无法完美解决，或者完美解决成本太高。

先调研一下：
- 根因：这个问题的根源是什么？
- 概率：这个问题出现的概率多大？
- 影响：后续不良影响和后果多大？
- 完美解决成本：这个问题能完美解决吗？完美解决的成本是不是太高？
- 简化方案：是否有简化方案，虽然不能完美解决，但成本大幅下降，结果可接受？

## 三、完善后要加的条目（草案，就这一条）

```
### ④ 方案尽量简化，锚目标态，不为低概率小影响纠结完美方案

评估"做到什么程度"时，默认选能达成目标态的最简方案，不追求完美——
可牺牲低概率、影响小、且完美成本过高的边角。

⚠️ 简化只能砍「防御的深度」，MUST NOT 砍「目标的范围」（与③的边界）：
· 目标态 producer 会产出的核心形态 → MUST 处理，不因"存量少见"缩水（③管这个）
· 边角失败模式的完美防御 → 可按 概率×影响÷完美成本 分诊，简化 + 记 todo

撞到"要不要为这个问题做完美方案"的纠结，先跑五问，别凭直觉钻：
  根因 / 概率 / 影响 / 完美成本 / 简化方案(成本大幅降、结果可接受的次优解)

MUST NOT 为一个低概率、影响小、甚至无法完美解决或完美成本过高的问题，
反复来回纠结完美方案。

止损/反沉没成本：方向一旦被证伪，MUST 立即止损换向，MUST NOT 在已被否定的
方向上继续优化/加码（同一方向被纠正 ≥2 次 / 起手前提被推翻 → 停下重定方向，
别在细节里打磨一个错的框架）。
```

**关键护栏**：`⚠️ 简化只能砍防御深度、不砍目标范围` —— 这是第 2 条与通则③不打架的唯一保证。
**先例（非空想）**：CLAUDE.md 基准 5(A21) 的"digest 整文件不解析、target 能不能跑真跑一遍"就是本条的隐式实践（完美解析无界语法成本太高 → 简化方案）。本条是把它显式化、通用化。

## 七、优化后的完整文案（四条通则 · 成品预览）

> 把你提供的规则去重、补边界、整合后的完整心法。①②③基于现有三条通则（保留关键护栏，不退化为口号），②补联网调研，④为新增。落地时以此替换真相源。
> `premise-verification.md` 规则 1/2/3 已被收进 ① 的一行摘要；其详版 + 实测实例仍留 `openspec/rules/premise-verification.md`（通则给摘要、rules 给详版）。

### 🟢 方案讨论四条通则（一切设计 / 优化 / 评审任务适用 · 违反即本次工作失败）

#### ① 能查的自己查，能调研的自己调研
答案在 **仓 / 机器 / 公开资料**里 ⇒ 自己去拿，查完**直接给结论**。
- MUST NOT 拿一个自己查得到的问题去占用人的注意力（"你们用什么测试框架？"——`package.json` 里写着）。
- **给结论，不给过程**："集成测试是 `make integration`，我跑过了，绿" —— 不是"Makefile 里好像有个 target，你确认下？"。
- **落笔前先证伪**；**引用必须真打开过**（不是"我记得它写着"）；动一个被多处消费的**常量 / 谓词 / 字符串**前，先 `grep` 谁在用它、有什么影响。（详版见 `premise-verification.md`）

#### ② 不确定的方案，先调研再给推荐 —— MUST NOT 甩开放题
拿不准时 MUST NOT 把几个选项原样丢给人——那是把调研的活布置给了人。
- 正确动作：先把能查的查了，带「**推荐 + 依据 + 代价 + 备选**」进人门，人只负责拍板。
- **「代价 / 后果」按决策三镜展开**：系统镜（耦合/依赖/复杂度/可回退）· 用户镜（体验/可感知行为/干扰）· 开发循环镜（心智负担/是否靠人/流程开销/复用）+ **一句主次判定**。（详版 = `spec-workflow` spec / `BASE-12`；命中 TG-23 才 MUST 书面写满，琐碎决策不强制——避样板税）
- **本地无相关代码的设计方案，主动联网找权威最佳实践来调研。**
- 三分判据：仓/机器/公开资料→自己查；查得到候选与依据→调研后给推荐；只在人脑子里（偏好/踩过的坑/拍板权/组织约束）→才问。

#### ③ 以最终目标为准，MUST NOT 拿现状反驳目标
判断"该不该做 / 做到什么程度"一律**锚目标态**，不受现有代码与设计的束缚。
- MUST NOT 用"现在代码不这么写""存量里没出现过""现状里很少见""现有设计不支持"来论证**目标该缩水**。
- 迁移中"旧数据还没有新形态"是必然——问"**目标态的 producer 会不会产出这种形态**"，不是"现存文件里有没有"。
- 🔴 评审高发区：现状是唯一摆在眼前的东西，"它现在能跑 / 没出过事"极易被当成"它是对的 / 不用改"。**评审基准是目标态。**

#### ④ 方案尽量简化，不为低概率小影响纠结完美方案
在 ①②③ 之上评估"做到什么程度"：默认选**能达成目标态的最简方案**，不追求完美——可牺牲**低概率、影响小、且完美成本过高**的边角。
- ⚠️ **边界（与③）：简化只能砍「防御的深度」，MUST NOT 砍「目标的范围」。**
  - 目标态 producer 会产出的**核心形态** → MUST 处理，不因"存量少见"缩水（③管这个）。
  - **边角失败模式**的完美防御 → 按 概率×影响÷完美成本 分诊，简化 + 记 todo。
- 撞到"要不要为这个问题做完美方案"的纠结，**先跑五问，别凭直觉钻**：
  - **根因**：问题的根源是什么？
  - **概率**：出现概率多大？
  - **影响**：后果多大？（按决策三镜看：系统 / 用户 / 开发循环三面）
  - **完美成本**：能完美解决吗？成本是否过高？
  - **简化方案**：有没有成本大幅降、结果可接受的次优解？
- MUST NOT 为一个低概率、影响小、甚至无法完美解决或完美成本过高的问题，**反复来回纠结完美方案**。
- **止损 / 反沉没成本**：方向一旦被证伪，**MUST 立即止损换向**，MUST NOT 在已被否定的方向上继续优化 / 加码。④ 上半管"别为边角完美过度投入"，本句管"别在错误方向上持续投入"——同源：资源该往值得的地方放。**触发信号**：同一方向被纠正 ≥2 次、或起手前提被推翻 → 停下重定方向，别在细节里打磨一个错的框架。

> **③④ 是一对张力锚**：③ 防"拿现状缩水目标"，④ 防"为边角完美过度投入"——边界那句 `砍防御深度 / 不砍目标范围` 是两者不打架的唯一支点。

## 八、决策三镜（判断维度）与四条通则的关系 —— 逻辑咬合，不物理合并

**用户问**："方案判断标准：系统镜 / 用户镜 / 开发镜，是否可以合并到一起？"

**调研结论**：三镜不是散落的想法，是**已深度固化的正式框架**——
- 权威 spec：`openspec/specs/spec-workflow/spec.md:22`（决策后果 SHALL 按三镜展开 + MUST 附一句主次判定）
- checklist：`spec-quality-base.md` **BASE-12**
- 专门的归档 change：`2026-07-05-three-lens-decision-framework`
- 评审流程：`sdflow-spec-review` / `sdflow-code-review` 的**决策登记区**都用它
- **带 TG-23 触发门 + 避样板税**：命中「≥2 合理方案 / 非显然设计」才 MUST 书面写满三镜，琐碎决策不强制。

**两者是同一套"方案判断标准"的两层，不是并列的两套**：

| | 管什么 | 层 |
|---|---|---|
| **四条通则** | 怎么查 / 怎么推荐 / 锚什么 / 简化到什么程度 | **过程纪律**（动作层） |
| **决策三镜** | 多方案时，后果从系统 / 用户 / 开发循环三面看 + 判主次 | **后果评估维度**（评估层） |

**接口**：通则 ② 的「**代价**」和 ④ 五问的「**影响**」，正是用三镜来展开的 —— 已在上文 ②④ 各加一句锚点连上。

**为什么不把三镜全文搬进通则块（物理合并）**：
1. 三镜带 **TG-23 触发门 + 避样板税**；四条通则进 fan-out FRAME、**一切任务无条件通用**。把带触发门的重框架塞进无条件通则块 → 每次琐碎决策都背三镜样板 = **违反三镜自己的避样板税，也违反 ④ 简化**。
2. 三镜已有自己的家（spec-workflow + BASE-12），那里更适合承载它的触发分层细节；搬进通则 = 凭空多一个漂移面（违基准 1 单一源）。

**∴ 正解 = 在 ②④ 建立引用锚点，让四条通则与三镜连成一套完整判断标准；三镜全文留在 spec-workflow / BASE-12。** 这就是"合并"的正确形态——逻辑咬合，非全文搬运。

## 九、权威最佳实践对照（联网调研 · 2026-07）

> 按通则 ④ 第 4 条（联网找权威最佳实践）调研三个角度，用 ④ 分诊后**只纳真缺口，其余如实标覆盖，避免样板税**。

**调研角度**：Anthropic《Building Effective Agents》· CLAUDE.md Best Practices 2026 · AI Agent Guardrails。

**对照结论 —— 绝大多数权威原则本仓已覆盖（且更深）**：

| 权威原则 | 本仓归属 | 覆盖 |
|---|---|---|
| 保持简洁 / 别过度 | ④（简化分诊） | ✅ 逐字对应 |
| 按影响分优先级、别为低风险过度防护 | ④ 五问（概率×影响÷完美成本） | ✅ 权威**逐字背书** ④ |
| enforcement 不靠模型自警 | 基准 1 机械化优先 + `sync --check` + 脚本兜底 | ✅ 本仓更具体 |
| 可观测 / 留痕 / 不静默 | 三镜「MUST NOT 静默采纳」+ checkpoint + hand-off | 🟡 已覆盖，未立通用条（**不新增**，边际收益低 = 样板税） |
| 分层防御 | 多镜 + 对抗 + 接地 + 冷层 | ✅ |
| 采纳 agent 视角 / 接地 | 接地镜（读真实代码 / 输出） | ✅ |
| 透明展示计划 | 全局 CLAUDE.md「先给计划 + todo」+ 决策登记区 | ✅ |
| 从 policy 出发 | spec-first workflow | ✅ |

**唯一真缺、且有本仓血泪背书的一条 → 止损 / 反沉没成本**（已并入 ④，见第三 / 七节）：
- 权威侧：CLAUDE.md 实践「走错两次别硬刚，clear 重来」。
- 本仓血泪：`doc-body-final-state-only`（四轮 18 面镜全在废弃分支里优化，无一看见起手式错了）、`rework-introduces-holes`。
- 填的缝：③ 锚目标态、④ 别过度投入，但都没管"发现大方向已被证伪时止损换向"。
