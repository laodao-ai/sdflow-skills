# 0018 · 机械校验器输出诚实：不可验输入须在信号里可见

> 状态：Accepted（2026-07-11，grill `mlh-p4-reason-code-validators` design 收敛）
> 关联：MLH roadmap 阶段4·4.D · adr/0006(b)（机械 prose MUST 脚本化）· adr/0008（gate 防御纵深·不假设纪律成立）· adr/0016（只读报告工具反静默方向）· CONTEXT「反静默守卫」「信任边界」「机器锚行」

## Context

4.D 三个 reason_code 校验器的输出**被下游决策消费**——`outside_voice_guard` 的码决定「复用 vs 重跑 outside-voice」、`hr_tg_intersect` 的码决定「是否单开领域 cross-model」、`review_disposition_check` 的码进 roadmap 收尾 checklist。grill 逐支死磕时，三个校验器各暴露一个**同型隐患**：校验器的裁决被一个**不可机械验证的输入**所界定，而初版设计都想 emit 一个「干净的二态信号」，把这个界定**藏起来**：

- **T81 假阴**：命中集来自 proposal 头部**已声明**的 `〔TG-NN〕`；作者漏声明高风险 TG，裸 `none` 会静默绿灯放行「跳过强制领域 cross-model」——而「是否漏声明」机械不可知（要判 change 内容）。
- **T82 假绿**：`## Review 处置` 格式三实例不统一 + 「未处置」无字面 token + 收尾句子串自指，「逐条已处置」机械不可达；一个只查「存在+非空」却叫 `review_disposition_check`、输出裸 `present` 的工具，会被误读成「处置已核」。
- **T80 假新鲜**：新鲜度用 `git log` 时间，看不到未提交改动 → 工作树 dirty 时「产物是否早于最新设计改动」不可确认，裸判「新鲜」会复用陈旧审查。

三者共性 = **机械校验器投射了它并不拥有的确信**。这正是 mlh F1 `check_lens_metric` truthy **假过门**的同型失效——不是「做错」，是「假装验了没验的东西」，且失效沿输出信号**传播进下游的错误决策**。adr/0016 已为**只读报告工具**立「反静默方向」；adr/0008 已立「gate 不假设纪律成立、防御纵深」。本 ADR 把这条从「报告 / gate」推广到**任何输出被消费的机械校验器自身的输出诚实**。

## Decision

**任何输出信号被下游决策消费的机械校验器，当其裁决被一个不可机械验证的输入所界定时，MUST 把该界定编码进输出信号本身，MUST NOT emit 一个与「已完整验证」不可区分的裸通过码。** 三种落地形态（按不可验输入的性质择一或组合）：

1. **暴露输入依据**（输入完整性不可验）：surface 判据所据的输入，让复审者能 sanity-check 缺口。例：`hr_tg_intersect` 输出 `none｜依据已声明:[TG-01,TG-19]`，而非裸 `none`——欠声明可审。
2. **在码里点名未核边界**（某子判定机械不可达）：输出码字面写明「什么没核」，使消费方不会把「部分通过」误读为「全过」。例：`review_disposition_check` 输出 `section-ok-DISPOSITION-UNCHECKED`，而非裸 `present`。
3. **朝「漏判有害」方向 fail-safe**（判据本身不可确认）：无法确认时取保守值，使「误放行」不可能、代价只是重跑。例：`outside_voice_guard` 工作树 dirty→`stale-dirty-tree`（重跑 outside-voice，重跑只是成本、复用陈旧才是危害）。

**配套铁律**：
- **(a) 完整性强制 ≠ 校验器职责**：「声明是否覆盖实际命中」「逐条是否已处置」这类需判 change 内容的完整性，是**模型 / spec-review 职责**，MUST NOT 塞进机械校验器兜底——校验器只诚实报告「据可见输入所得」。
- **(b) 测试 MUST 含假信心陷阱负例**：子串自指（收尾句「无『未处置』」）、欠声明、dirty 树等——钉死「不假绿 / 不假阴 / 不假新鲜」。
- **(c) 与 fail-closed 区分**：坏输入（文件缺失 / 单一源损坏）→ `EXIT_FAIL` fail-closed（D5）；**可读但不可验**的输入 → 上述三形态的**信号内诚实**（非崩溃、非静默通过）。二者互补。

## Considered Options

- **裸二态信号（否决）**：`none` / `present` / 「新鲜」——最简，但把不可验界定藏进一个消费方会过度信任的干净码，是假绿/假阴/假新鲜的温床，违 adr/0016 反静默精神。
- **校验器兜底完整性（否决）**：让脚本去判「是否漏声明 / 逐条是否处置」——需判 change 内容，机械不可达；强行做只会用子串/正则制造新的假阳假阴（T82 实证）。
- **信号内诚实（采纳）**：暴露依据 / 点名未核 / fail-safe——成本是输出码更啰嗦、消费方需读懂，换来假信心不再静默传播。

## Consequences

- 三校验器输出码非最简，但**信任边界焊进信号**、可观测、可审计（承 CONTEXT「机器锚行」精神）。
- 为未来同类「输出被消费的机械校验器」立判据：先问「我的裁决被什么不可验输入界定？」→ 按三形态之一把它显式化。
- 不改变「机械活交脚本、模型只做判断」——反而更精确地划出机械与判断的界：**机械报告可验的、诚实标注不可验的、把完整性判断留给模型。**
