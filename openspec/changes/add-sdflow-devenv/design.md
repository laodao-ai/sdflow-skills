## 上位：身份定调（操作者 2026-07-14 拍定）

> **「这个 skill 是辅助我来搭建开发测试环境的，同时提醒我要考虑哪些事情别忘了。」**

**skill 是副驾**——不是替人开车的生成器，也不是查人岗的审计官。

**这一句凌驾于一切机制设计，并直接改判了「防漏」的形态：**

| | |
|---|---|
| **它的第一功能** | **「提醒你别忘了考虑 X」**——把「一个有经验的人会问的问题」一条不落地问出来 |
| **「一层不许留白」怎么兑现** | **由「问」兑现，不由「拦」兑现** |
| **载体** | `references/` 的清单 + `SKILL.md` 的提问纪律（= **A 层，脑**） |

> **一个不会拦截、但把该问的都问到了的 skill，是合格的。**
> **一个拦得死死的、但没提醒你「你还没想过 e2e」的 skill，是失败的**——哪怕它一个空格子都没放过。

## 九条决策（grill 收敛，2026-07-14）

| # | 决策 | 代价 / 它推翻了什么 |
|---|---|---|
| **D1** | **「留白」= 该问的没问出口，不是格子填空。** `⚠️ 待定` 是合法产物（即便十五格全待定）。兑现靠 **A 层清单 + 代价可见**（渲染横幅 + 收尾报告），**机械层不兜底** | **代价：核心承诺没有任何机械兜底。** 一个偷懒的运行**技术上完全合规**。接受它——见 `adr/0021` 的「代价」节 |
| **D2** | **落地物按「新建 / 改已有」两类风险分**，不按文件类型。**跑测试的载体交模型现场判**（Makefile？npm script？裸命令？）。`verification.method` = 一条裸命令 | 推翻 §1.4「Makefile target —— **门禁逻辑在此**」（污染 15 个小节）· **机制 B 整节溶解**〔**A24**〕 |
| **D3** | **「层」= 保真度刻度**（按「穿过哪些真实边界」判定），**不是测试类型分类法** | 与 `lane-patterns` 的形态阶梯**合成一个轴**〔**A25**〕 |
| **D4** | **五槽 → 六槽**：新增 ⑥「**这层证明了什么 · 看不见什么**」，三种状态都必答 | 「不适用记后果」从特例升为普遍维度 |
| **D5** | **skill MUST NOT 删除文件**（爆炸半径不受控）。**可改内容**：整体失效→顶部加标记内容留着；部分失效→**真删那段** | 推翻「三种删源处置」+「删源前工作区必须干净」+ 冷审「删源镜」〔**A26** · `adr/0022`〕 |
| **D6** | **层无独立状态——从泳道投影算出。**「已实现 / 人工」两词废弃 | 「已实现」实指「有脚手架」（**从未跑绿也能自称已实现**）⇒ **它在装**〔**A25**〕 |
| **D7** | **切线 = 测试 vs 非测试。** `testing-strategy.md` 是测试的唯一真相源（六槽完整） | 推翻「方法 vs 操作」（连带推翻 `05` §3.1）——那会把「每层交代清楚」**劈成两半**〔**A27**〕 |
| **D8** | **五步的 ② 改为「三层框架逐层问 → 泳道是槽③④的答案」**；⑤ 从「产出」降为「渲染」 | **核心承诺在流程里原本没有步骤**——A23 的病长在了流程上〔**A28**〕 |
| **D9** | **`environments.md` 零 JSON 载体、零机械渲染**——**但有模版、有提问清单、由 skill 逐槽问出来** | 了结「十六槽 MUST 从 JSON 渲染却无承载字段」那条悬空 MUST〔闸门 2，同 A22〕 |

## 这九条其实是同一条

**A23 的诊断**：*全部力气花在机械可验的东西上，核心承诺零字*（18 个 Task 里 10 个是机械防漏基础设施、1646 行代码，而 `references/` + `SKILL.md` **零字**）。

**grill 发现它不只长在代码里——它长在文档的每一层：**

- **长在流程里**（D8）：五步全绕着泳道转——**因为泳道能 fork、有 exit code、机械可验。而「问人十五个问题」不能。**
- **长在数据模型里**（D2/D6）：`source.kind` 枚举、层的独立状态——**都是为了让机械层有东西可校验而存在的。**
- **长在文档切线里**（D7）：把测试劈成「方法/操作」两半——**读者要拼，但机械好切。**
- **长在词汇里**（D3/D6）：「已实现」「层」——**含混，但能塞进枚举。**

> **⇒ 九条修改的共同方向：把设计的重心，从「机械层校验得了什么」搬回「人需要被问什么」。**

## 三层架构（`07` §3）

| 层 | 是什么 | 载体 | 分量 |
|---|---|---|---|
| **A · 脑** ⭐ | ① 三层×六槽提问清单 ② 形态推导框架 ③ 归属判据 ④ 五步编排 ⑤ 冷审镜单 ⑥ 负面知识 | `references/` + `SKILL.md` | **skill 的全部价值。这层退化 = skill 不存在** |
| **B · 手** | scaffold · **verify-lane（真跑）** · render · inject | `devenv_scaffold.py` | **在建造**，不在评估 |
| **C · 记性** | 一份 JSON：让 `continue` 能续 · 让命令表不双写 | `devenv_schema.py` · `devenv_paths.py` · `devenv_lint.py` | **A 和 B 的记事本**——不是产物的质检员 |

**实测配比**：A 层 1350 行 · B+C 1094 行 —— **脑不比手轻**。

> **C 层 MUST 保持轻**：**若哪天 `scripts/` 又比 `references/` 重，就是审计官回来了。**

## 已知的、接受的边界（如实记）

| 边界 | 为什么接受 |
|---|---|
| **核心承诺无机械兜底** | 「问没问」与「跑没跑」同构——agent session 里模型是唯一执行者，**机械上不可区分** ⇒ 属防伪，机械层不管。硬造信号就是假绿，**而假绿比诚实的语义层更危险** |
| **vacuous 机械层堵不死** | `assert True` 类语义恒真，**任何外部插桩都堵不住**（三条方案全部证伪）。要堵只有变异测试，判为太重 ⇒ **归冷审 vacuous 镜——唯一防线** |
| **`verified` 不覆盖被测实现** | 覆盖它需要跨语言 import 图分析，零依赖做不到〔A19〕⇒ **`verified` 是 `verified-at <sha>`，不是当前绿灯**。**诚实呈现，不加拦不全的锁**〔A23〕 |
| **不删 ⇒ 双写留存** | **看得见的双写，是一个待办；看不见的误删，是一个事故**〔`adr/0022`〕 |
| **A-8 零实证** | 「模型能为三层提出**像样的**验证方法」——**至今未在真项目上验过**。**tasks §7 的试点就是为验它**。skill 已可跑，不再是纸上谈兵 |
