# add-sdflow-devenv

> 真相源 = `docs/sad/07-devenv-skill-design.md`。被否方案见其**附录 A1–A28**（本文只留编号引用）。

## Why

**技术架构定了之后，「怎么开发、怎么测试」没有任何落点。** 每个项目都要重新想一遍：单元测试怎么写？集成测试连什么？e2e 要不要做？——**而最容易被跳过的，恰恰是最贵的那几个问题。**

生态已有**时间轴**（`sdflow-roadmap`）与**空间轴**（`sdflow-architecture`），**过程轴缺位**。`sdflow-architecture` 交棒时只能「指出不代写 + 给模板路径」，把操作者留在手搓状态。

**核心承诺（操作者定调）**：**不管什么项目**，跑完都拿到一份测试与验证的策略与框架——**单元 / 集成 / e2e 三层，每层交代清楚**；做不了的写「不适用 + 后果」，要人做的写「人怎么做」；**一层都不许留白**。框架**后续可迭代**，不是一次定死。

**⭐ 身份定调（凌驾于一切机制设计）**：

> **「这个 skill 是辅助我来搭建开发测试环境的，同时提醒我要考虑哪些事情别忘了。」**

**skill 是副驾**——不是替人开车的生成器，也不是查人岗的审计官。
**它的第一功能是「提醒你别忘了考虑 X」。**

### 天花板声明（MUST 如实记，MUST NOT 佯装）

| 我们**不**保证 | 为什么 |
|---|---|
| **测试方法有效**（smoke 不是 vacuous） | `assert True` 类语义恒真，**任何外部插桩都堵不住**（三条机械方案全部证伪〔A12/A13/A14〕）⇒ **归冷审 vacuous 镜——唯一防线** |
| **`verified` = 当前能跑** | 它是 **`verified-at <sha>`**——**一次历史执行的记录**。任何 digest 都覆盖不了被测实现〔A19〕⇒ **业务代码一改，那个绿灯就在说谎** |
| **skill 真的问了那十五个问题** | 「问没问」与「跑没跑」同构——agent session 里模型是唯一执行者，**机械上不可区分** ⇒ 属防伪，机械层不管〔`adr/0021`〕 |

> **skill 保证「有方法 · 执行了 · 结果被认可」。它 MUST NOT 保证「方法有效」。**

## What Changes

**新 skill `sdflow-devenv`**，五步：

```
① 事实采集 + environments.md 十槽逐槽问
② ⭐ 三层框架逐层问六槽 → 泳道随之落定    ← 核心承诺在这一步产出，人门重心
③ 落地脚手架 + 尽可能跑一遍确认（真 fork 执行）
④ 冷审 + 人门
⑤ 渲染 + 入口 + 交棒
```

**产出四样**（不只是文档）：

| # | | |
|---|---|---|
| 1 | ⭐ **`testing-strategy.md`** | 测试的**唯一**真相源——三层 × 六槽，**一层一个完整交代**。从 JSON 机械渲染 |
| 2 | **`environments.md`** | 非测试——dev 搭建（含 ⭐**常见坑**）+ deploy 发布（含 ⭐**回滚**）。**有模版、逐槽问出来，铺完归人 own** |
| 3 | **落地物**（真代码） | smoke · harness · 依赖服务启停 · doctor。**载体交模型现场判**〔A24〕 |
| 4 | **入口** | `opsx-devenv` 托管块 + `openspec/INDEX.md` |

**⭐ 第六槽是这个 skill 存在的理由**：**「这层证明了什么 · 看不见什么」**。
**人最容易忘的不是「用什么框架」**（一搜就有）——**是「我这层全绿了，可我还是不知道什么」。**

**上下游**：`sdflow-architecture` 交棒指向本 skill（不再只给模板路径）· `sdflow-maintain` 调 `devenv_lint`（**这是「不强制完成」的另一半**）。

## Success Metrics

| 指标 | 基准 → 目标 | 度量方式 |
|---|---|---|
| **三层无留白** | 无框架 → **三层 × 六槽全被问过**（`⚠️ 待定` 是合法答案，但**必须是被问过之后的**） | 试点项目的 `testing-strategy.md` 逐格核 |
| **至少一条泳道真跑绿** | 0 → **≥1 条 `verified`**（脚本亲自 fork，有真实 exit code） | `.devenv.json` 的 `evidence.exit == 0` |
| **⑥ 槽不是套话** | — → **每层的「看不见什么」是这个项目特有的一句** | 冷审盲区镜：**这句话对别的项目也成立吗？** |

## Non-Goals

- ❌ **保证测试有效**（vacuous）—— 见天花板声明
- ❌ **删除操作者的任何文件** —— **skill 只改不删**〔`adr/0022`〕
- ❌ **替操作者装系统依赖** —— 给命令 + doctor
- ❌ **debug 跑不绿的泳道** —— 职责是「建 + 验」，不是「调通」。**跑不绿是合法状态**
- ❌ **解析 Makefile / shell** —— 无界语法面禁手搓〔A21〕。**让工具自己判**
- ❌ **生产运维 runbook**（on-call / SLO）—— 只到 deploy 操作为止
- ❌ **业务测试用例** —— 归各 change

## 开放问题

| # | | 现状 |
|---|---|---|
| **Q1** | **A-8 零实证**：「模型能为三层提出**像样的**验证方法」是核心前提，**至今未在真项目上验过** | **skill 已可跑** ⇒ tasks §7 的试点就是为验它。**不再是纸上谈兵** |
| **Q2** | 未覆盖的依赖形态（Java 服务 / 移动 app / 分布式）无参考实例 | **兜底：临场推导 + 显式标注 + 登记 todo。MUST NOT 罢工**〔A24 的一般化〕 |
| **Q3** | 是否给 `devenv_lint` 加**硬门禁**（`ship_gate` 式拦截） | **暂不加**——`adr/0021`：**代价可见 > 机械拦截**。`sdflow-maintain` 提供「更响的提醒」 |

## 假设

| # | 假设 | 若不成立会怎样 |
|---|---|---|
| **A-8** | 模型能为三层提出**像样的**验证方法 | **整个 skill 的价值坍塌**——它会问出十五个问题，然后给出十五个套话答案。⇒ **必须靠真项目试点证伪** |
| A-9 | 「保真度刻度」这个层定义**对所有项目都可判** | 撞到判不了的项目 ⇒ 该项目的形态进 `lane-patterns` 补格 |
| A-10 | 操作者愿意回答十五个问题 | 若嫌烦 ⇒ 大量 `⚠️ 待定`，**而那是合法的、可见的**——不是失败，是「这次只走到这儿」 |
