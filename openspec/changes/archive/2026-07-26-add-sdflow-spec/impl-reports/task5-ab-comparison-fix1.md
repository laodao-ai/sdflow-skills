## 2. B（Important）· 「SIGKILL 却拿到 JSON」自相矛盾 —— **已核，订正为实际情形**

复审的判断正确：**SIGKILL 与「拿到完整 JSON」不可并存**。自己去核的结果是——**原稿三处都错**：

`terminal_reason=aborted_streaming` · `subtype=error_during_execution` · `stop_reason=tool_use` ·
`errors=["[ede_diagnostic] result_type=user last_content_type=n/a stop_reason=tool_use"]`。

报告里这条**明写为推断、不是实测**，未升格成结论。

**但复审假设的反向支，我实测后发现不成立，如实记录**：
复审推测「中断轮的计费**可能整体丢失** ⇒ thin 的 $9.06 是低估」。
其独立实测（`-s KILL` → 0 字节；`-s TERM` → cost 0）**对的是外部信号场景**，
而本轮这两轮**不是外部信号**（见 §2）。实际数据：

- 两轮的 `total_cost_usd` **不是 0**（$2.8426 / $2.9439），`usage` 满额（thin turn02：cacheRead 3.28M、output 31K）。
- **一致性自检**：把 12 轮按 Opus 标准价（in \$5 / out \$25 / cacheRead \$0.5 / cacheWrite-1h \$10 每 MTok）折算，
  **含这两轮在内 12/12 轮的 `costUSD` 与折算值之比 = 1.0000**。

⇒ 「计费整体丢失」这一支**在本数据上不成立**。

**∴ 我没有把它写成「双向等强」——那会是另一个方向的过度声称。**报告写的是**两支证据强度不对称**：

| 支 | 方向 | 证据状态 |
|---|---|---|
| ① 中断轮开销部分白花（turn03 `-r` 续跑时部分重做）+ 多一次 turn 边界 | 抬高 thin/legacy | **有证据** |
| ② 中断轮用量少报 | 压低 thin/legacy | **无正面证据**（比值闭合），但**不可排除且无界** |

**② 为何仍不可排除**（这是幅度作废的真正理由）：比值闭合只证明「费用与**自报**用量一致」，
**不能**证明自报用量覆盖了该轮全部 API 活动——若计数器提前停止，费用与 token 会**一起**少报，
比值仍是 1.0000。该支偏差量**无界** ⇒ **幅度不可作结论依据**，结论只能退到「未观察到更便宜」。

> 🔴 这是本轮**唯一一处与复审指令的实质分歧**，已按「有异议 → 说出来，然后照原样推进」处理：
> 复审要求的**四项动作全部照做**（降级 / 作废 / 清措辞 / 双向），
> 只是在**理由**上如实写出「②的依据不是计费丢失，而是自报用量完整性无法证明」。
