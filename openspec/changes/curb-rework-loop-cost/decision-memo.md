# 决策纪要 · curb-rework-loop-cost

## 目标态

把全量测试的运行次数与 fix 轮次解耦（收口跑一次），并给返工循环装上熔断与出票源头闸门。

  这一内聚交付物，⑫（devenv 格式解析手段对照表）与 ⑤（出票闸门）是同一件事的两面
  （⑤ 拦截、⑫ 提供手段出处），fold 进来内聚性更好且为纯 Markdown、零 blast radius；
  **砍掉的候选**：⑪（YAML 界外 fail-loud）——交付物不同（解析健壮性 vs 循环行为）、
  改 5 个脚本的全流程承重解析面、blast radius 与 prose 契约改动不同量级，单开 change；
  第三层「格式解析体检工具」——它 MUST 以 ⑫ 的对照表为单一源，⑫ 未落地前做它必然
  硬编码一份判据并随后漂移，故顺序上必须在 ⑫ 之后。（人 2026-07-31 明确确认）

- **D1 ① 的中间轮范围改由「确定信息」界定，取消「受影响层」提法** — 依据：C6 证伪；
  中间 fix 轮 = **unit 全层**（整层跑、不筛选）+ **上轮失败的具体用例**（有记录的确定信息）；
  集成 / e2e 整体推到收口，**按成本分档而非按影响面分档**，与 ② 的 quick/full 咬合。
  **砍掉的候选**：① 初版的「只跑受影响层 + 上轮失败层」——「哪层受影响」是不可靠判断，

  修正后严格优于现状，非新增风险。（人 2026-07-31 明确确认）

  **砍掉的候选**：「一轮即止、残差全 defer」——虽更省且贴合 `sdflow-code-review/SKILL.md:7-8`

## 接受的边角

- **集成层回归的暴露时点后移到收口，修复更贵** — 概率：中（集成层确实会有回归）；影响：中
  （发现越晚越贵）；完美成本：过高（test impact analysis 需覆盖率或依赖图，三个消费栈
  pytest / go test / vitest+playwright 无统一现成工具）。**为何接受**：现状是集成/e2e
  在中间轮**根本没被可靠跑过**（8 红测实证），修正后严格优于现状——这不是新增风险，
  而是把一个隐性的 fail-open 换成显性的、有收口兜底的延后。

- **中间轮会跑一部分「其实无关」的 unit 用例** — 概率：高（必然）；影响：低（unit 是三层中
  最便宜的一层）；完美成本：同上过高。**为何接受**：用少量确定成本换掉一个不可靠判断，
  方向正确且成本有界。

- **硬上限阈值（熔断 3 轮 / 复审 1 轮）是启发式，非推导所得** — 概率：中（可能误伤真·不同问题
  或放过第 3 轮才暴露的真问题）；影响：低（熔断处置是**升 strong 档复核**而非直接放过，
  代价有界）；完美成本：过高（"多少轮算异常"无客观判据）。**为何接受**：通则④——
  3 由两个病例校准（均在第 3 轮已可判定，且本仓 7 天 16 change 中 fix 轮 ≤2 者占多数，不误伤），
  1 由「修复本身需被审一次、但不需被审第二次」的对称性定；落地后如误伤再调，不预先纠结。

- **⑤ 的判据是指令层约束，非机械门** — 概率：中（出票时仍可能漏判）；影响：中；完美成本：
  过高（"这个语法面有界吗"无确定性信号，属 adr/0018 的语义残余）。**为何接受**：
  C4 的正例（tasks.md:30 主动写下「MUST NOT 解析 Markdown 结构」）证明该判断在出票时**做得出**；
  ⑫ 提供手段出处降低漏判率。MUST NOT 声称它是机械保证。

## 三镜代价

**命中 TG-23**（D0 三选一、D1 两方案、D2 两方案，均为非显然设计选择）⇒ 逐条写满。

**D0 · 本 change 范围 = 八项（⑪ 单开）**

  与七项的 prose 契约改动**不是一个 blast radius 量级**；混编会让七项被 ⑪ 的风险拖着走。
- **用户镜**：无差别。
- **开发循环镜**：**反向代价**——多开一个 change 多付一整轮 workflow 固定成本（spec→设计审→
  实现→代码审→done）。这是选项 B/C 的真实优势。
- **主次判定**：**系统镜为主**。⑪ 的失败模式是「工具链挂掉」，七项的失败模式是「编排指令不理想」；
  拿承重面赌流程成本不划算。

**D1 · 中间轮范围由确定信息界定**
- **系统镜**：判据从模型判断换成可机械求值的信号，失效方向由 fail-open 翻转为 fail-safe；
  代价是精确性下降（跑一些无关 unit 用例）。
- **用户镜**：无感知（阶段三无人类门）。
- **开发循环镜**：中间轮反馈更快（不等集成/e2e），但集成层回归后移到收口才暴露。
- **主次判定**：**系统镜为主**——可靠性问题优先于精确性与成本。

- **用户镜**：无差别。
- **开发循环镜**：保留一轮复审的成本（选项 A 更省），但有硬上限、成本可控。
- **主次判定**：**系统镜为主**——盘面缺口与文档分叉都是正确性问题，省一轮是成本问题。
