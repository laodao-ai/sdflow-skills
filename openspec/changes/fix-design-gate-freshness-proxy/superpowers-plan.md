## Global Constraints

以下逐字摘自本 change `design.md` 的 Compliance 条款、ADR-1 求值口径与判定流图注，以及
`ship_gate.py` 头部的 BR-6 护栏。**每个 implementer / reviewer 子代理共享这一份注意力透镜。**

**Compliance（design.md）**

- 判据 MUST 限于**行级等值比较**（勾选框标记归一化后逐行比对）；**MUST NOT** 做语义 diff、**MUST NOT** 解析 markdown 结构、**MUST NOT** 把豁免面扩到勾选框以外的任何差异形态〔spec-review-amendment〕。
- 豁免 MUST 仅在提交**只触及 `tasks.md`** 时成立；同一提交若还触及其他被监视路径，照判失鲜。
- 判据 MUST 逐提交独立求值，MUST NOT 依赖工作树状态或任何跨提交状态。
- `proposal.md` / `design.md` / `specs/` 的失鲜口径 MUST 逐字不变。
- 既有 `checkpoint(impl-review)` 精确式豁免（BR-7）MUST 不受本 change 影响。
- 新增判据分支 MUST 有变异验证：删掉该分支，对应用例 MUST 转红。

**判定流图注（design.md，🔴 上一条 Compliance 的口径消歧）**

```
  本帧落在 design 域监视集内的路径集 == {tasks.md} ? ──no──► STALE
        （🔴 不是整个 commit 的文件列表——checkpoint 走 add -A，
          真实完成提交必然打包源码；按整 commit 求值 ⇒ 豁免永不触发）
```

**ADR-1 求值口径（design.md）**

> **求值口径**：判据只比对 `tasks.md` 在该提交前后的两版内容，**逐提交独立求值**，不依赖任何跨提交状态、不依赖工作树。**MUST NOT** 做语义 diff、**MUST NOT** 扩展到勾选框以外的任何差异形态（措辞、格式化、错别字一律照判失鲜——见 Non-Goals）。

**Non-Goals（design.md，本 change 明确不做）**

- **注释 / 措辞类改动的内容感知豁免。** `design.md` / `specs/` 上「澄清性注释」与「设计变更」之间无确定性信号——注释本身即设计沟通，implementer 读到即照做。做内容感知等于在无界语义面上开补丁循环（基准 5）。该面的既有正解是 `checkpoint(impl-review)` subject 声明式豁免。
- 改动 `code` 域失鲜判据（本 change 只动 `design` 域）。

**BR-6 护栏（`ship_gate.py` 现有注释，逐字）**

> MUST NOT 加 --no-merges/--first-parent〔BR-6 护栏〕——头注释承诺 merge 内部提交逐一枚举不漏检；--no-merges 会改变 merge 场景失鲜语义。

**读取保真（design.md 代价条款 + tasks 1.1c/1.1d）**

- 前后两版内容读取 MUST 显式判 returncode；任一侧失败 ⇒ **直接保守判失鲜**，MUST NOT 依赖空串巧合不等（双侧失败会得 `"" == ""` ⇒ 判等值 ⇒ **放行真实设计改动**）。
- 读取 MUST 保真：MUST NOT 复用会 `.strip()` / 文本解码替换的路径（吞首尾空白、末尾换行、CRLF、非 UTF-8 字节，四者各自可造假等值）。

### Task 1: 设计门能看见内容，且看不清时一律保守判失鲜

**Blocked-by:** none
**R-ID:** SW-1（阶段三编排台账确定性 · 勾选框以外的一切 tasks.md 改动照判失鲜）

设计门在 design 域逐提交判新鲜度时，获得两项它现在没有的能力：**区分「本提交落在 design 域监视集内的路径集」与该提交触及的其余路径**，以及**取到指定提交前后两版 `tasks.md` 的原始字节**。

本票**不引入任何豁免**——所有情形仍照判失鲜，对外可观察行为与本票之前**逐字一致**。它交付的是「判定有能力看见内容」这件事本身，以及看不清时的**保守方向**：任何取不到、读不准、形态不合格的情形，一律判失鲜，绝不因读取失败而放行。

- [x] 能对单个提交求出「落在 design 域监视集内的触及路径集」，与该提交的完整文件列表是两个不同的量
- [x] 能取到指定提交前后两版 `tasks.md` 的原始字节，读取保真（不经文本解码替换、不去首尾空白、不改行尾、非 UTF-8 字节不被吞）
- [x] 读取的返回状态被显式检查；任一侧失败 ⇒ 判失鲜（**不得**依赖两个空值恰好相等或不等）
- [x] 前版不存在（该提交中新建）⇒ 判失鲜
- [x] 后版不存在（该提交中删除 / 迁走）⇒ 判失鲜
- [x] 该提交对 `tasks.md` 的变更不是普通内容修改（重命名 / 复制 / 类型变更 / 仅权限位变更，此类形态前后两版字节可能完全相同）⇒ 判失鲜
- [x] merge 提交下「前版」相对**每个** parent 各自定义，且未引入 `--no-merges` / `--first-parent`（BR-6 护栏逐字不动）
- [x] 既有全部失鲜用例逐字保持绿，本票不改变任何一条既有判定
- [x] 变异验证：删除任一条保守回落分支 ⇒ 对应用例转红

### Task 2: 纯勾选框翻转不再撞门

**Blocked-by:** 1
**R-ID:** SW-1（Scenario 纯勾选框翻转不失鲜 / 勾选框以外的一切 tasks.md 改动照判失鲜）

本 change 的 P0 交付。提交若在 design 域监视集内**只**触及 `tasks.md`，且前后两版在勾选框标记归一化后**逐行等值**，则不判失鲜；其余一切照判。

🔴 **最贴近真实故障的形态是打包提交**：完成任务的提交必然同时带上源码改动。该提交同时触及监视集**之外**的路径（源码、`impl-reports/` 等）**不影响**豁免资格。若把「只触及 `tasks.md`」按整个 commit 的文件列表求值，豁免在真实世界**永不触发**，而全部其余用例仍会通过——这是本票最需要被用例钉死的一处。

- [x] 正例：提交在监视集内只触及 `tasks.md`、只翻勾选框 ⇒ 不失鲜
- [x] 🔴 正例（主用例）：同一提交既纯勾选 `tasks.md`、又改仓库别处源码 ⇒ **不失鲜**
- [x] 正例：勾选框由 `[x]` 翻回 `[ ]`（反向）⇒ 不失鲜（归一化对称）
- [x] 归一化仅替换 `[ ]` / `[x]` / `[X]` 标记本身，不触碰缩进 / 空白 / 其余字符
- [x] 归一化锚定到 task-list 行首；fenced code block 内的标记不参与归一化
- [x] 负例：fence 内 `[ ]`↔`[x]` 翻转 ⇒ 失鲜
- [x] 负例：表格 / 行内反引号 / 散文字面量中的 `[ ]`↔`[x]` ⇒ 失鲜
- [x] 负例：同一行含多个标记，task marker 与文档字面量反向翻转 ⇒ 失鲜
- [x] 负例：纯行重排（零字符改动）⇒ 失鲜（比较按位置对齐，**禁 LCS**——LCS 下重排的删除行与插入行逐字节相同）
- [x] 负例：勾选框 + 同行措辞改动 ⇒ 失鲜
- [x] 负例：勾选框 + 新增 / 删除一个任务段（范围变化）⇒ 失鲜
- [x] 负例：只改缩进 / 空白（无勾选框变化）⇒ 失鲜
- [x] 负例：CRLF↔LF、末尾换行增删、首尾空白 ⇒ 失鲜
- [x] 负例：同一提交同时触及 `tasks.md`（纯勾选）与 `design.md` ⇒ 失鲜
- [x] 变异验证：删内容判据 ⇒ 正例红；**删监视集限定、改按整 commit 求值 ⇒ 打包正例红**；删 fence 感知 ⇒ fence 负例红；删行首锚定 ⇒ 字面量负例红；改位置对齐为 LCS ⇒ 重排负例红

### Task 3: 内容豁免与既有 subject 豁免的优先级有唯一解

**Blocked-by:** 2
**R-ID:** SW-1（Scenario 内容豁免与既有 subject 豁免的优先级 / 豁免面 MUST NOT 由被监管方书写的声明决定）

两条豁免通道现在共存，其交互必须有唯一确定的答案，不能依赖实现顺序的巧合。

`checkpoint(impl-review)` 精确匹配 MUST 在读取任何内容**之前**短路判豁免；其余任何 subject——包括 BR-7 要拒的变体形态、空 subject、普通 subject——都**可以**凭内容判据获得豁免。BR-7 的既有语义须读作「**变体不因 subject 获豁免**」，而非「变体必然失鲜」：一个 subject 写成变体形态、内容却是纯勾选翻转的提交，走内容通道豁免是正确的。

- [x] subject 精确匹配 `checkpoint(impl-review)` 或以 `checkpoint(impl-review):` 起首 ⇒ 在读取任何内容之前短路豁免
- [x] 变体 subject（如带尾串垃圾的形态）+ 纯勾选内容 ⇒ 经内容通道豁免
- [x] 变体 subject + 语义改动 ⇒ 失鲜
- [x] 空 subject / 普通 subject × 纯勾选 / 语义改动 ⇒ 各自按内容通道判定
- [x] 真值表：`精确 / 变体 / 空 / 普通 subject` × `纯勾选 / 语义改动` 共 8 格，逐格锁定为用例
- [x] 既有 subject 豁免回归用例全绿（裸形态与带冒号形态豁免、尾串垃圾失鲜、变体失鲜、豁免与普通提交交错失鲜）
- [x] 豁免面不由被监管方书写的任何声明单独决定：内容通道的判据取自内容本身，不取自 subject 或文件存在性

### Task 4: 撞门者被告知撞在哪、下一步做什么

**Blocked-by:** 2
**R-ID:** SW-1（Scenario 失鲜 REFUSE_START 须携带触发点与处置指引）

设计门失鲜拒绝时，撞门者当前只能看到「结论陈旧」，无从判断下一步。拒绝结论须携带**结构化**触发点，人读与机读两侧同步。

**默认处置只推荐「重跑设计门」一条。** MUST NOT 把 `checkpoint(impl-review)` 写进默认处置指引：它是显式越权口，且**对撞门者根本无效**——豁免逐提交求值，已经触发失鲜的那个提交不会因为**后补**一个 `checkpoint(impl-review)` 提交而被追溯赦免；写进指引等于教人去做一件不起作用的事。

- [x] 失鲜拒绝的人读原因携带触发提交的短 sha、subject、触发路径
- [x] 携带**分类原因**：混合路径 / 非勾选框变化 / 前后版缺失 / 状态不合格
- [x] 机读输出（JSON）同步这些字段，供 agent 直接取用，免二次解析散文
- [x] 默认处置只推荐重跑设计门；`checkpoint(impl-review)` **不出现**在默认处置指引中
- [x] 纯诊断：不参与判定、不改退出码、不改任何既有判定结论
- [x] `code` 域的新鲜度取值字符串**逐字不变**（下游读点依赖它）
- [x] 变异验证：删触发点增强 ⇒ 对应断言转红
