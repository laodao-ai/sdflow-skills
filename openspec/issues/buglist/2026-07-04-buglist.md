## B1: 实现进度窗口以 plan 落地 commit 为排他起点——task 锚与 plan 同 commit 时被漏数（已复现 11/12 误报）

| 属性 | 值 |
|------|------|
| 模块 | `sdflow-ship/scripts/ship_gate.py` |
| 优先级 | P2 |
| 状态 | FIXED |

**关联文档**：`openspec/changes/cross-model-outside-voice/design.md`

**现象**：checkpoint-commit.sh 的 add -A 把未提交的 superpowers-plan.md 随 task1 checkpoint 一起入库 → gate 窗口 c7ce5c4..HEAD 排他起点=task1 自身 commit → done_tasks 缺 1、CONTINUE_IMPL 误报 11/12；本轮以锚补记空 commit（6b94531）人工越权绕过

**根因**：`done_task_ids` 以 plan 落地 commit 为窗口**排他**下界（`plan_first_sha..HEAD`）；当 plan 首次提交与 task1 checkpoint 同 commit（checkpoint 的 `git add -A` 携带未提交 plan），task1 锚落在窗口起点 sha 自身而被排他区间排除。

**修复方案**（ship-gate-hardening design D1）：
- `done_task_ids` 追加 `git log -1 --format=%s <plan_first_sha>` 解析窗口起点 sha 自身 subject，窗口语义改为**闭区间** `[sha, HEAD]`。锚测 `test_plan_task1_same_commit_counts`。

**影响范围**：仅 ship_gate 实现进度判定；修复后 plan 与 task1 同 commit 不再漏数，其余窗口行为不变。
> 2026-07-04 状态：PROPOSED → FIXED（ship-gate-hardening (archived 2026-07-04)）

## B2: design-approved 新鲜度守卫把阶段三合法产物（code-review 的 [impl-review-fix] 对 design/tasks 的修订）误判为拍板失鲜（REFUSE_START）

| 模块 | `sdflow-ship/scripts/ship_gate.py` |
| 优先级 | P2 |
| 状态 | FIXED |

**关联文档**：`openspec/changes/cross-model-outside-voice/design.md`

**现象**：code-review 步按工作流设计对 design.md（安全节措辞修正）与 tasks.md（勾选回填）打 [impl-review-fix] 补丁并 checkpoint(impl-review) 后，gate 判「design-approved 之后四件套被改动→拍板失鲜」exit 3，阻断本应继续的 RUN_VERIFY；本轮已按用户同类先例（拍板重申补锚）越权续跑

**根因**：`is_stale` 的 design-approved 新鲜度守卫把锚之后对四件套的**任何**提交都判失鲜，未区分阶段三合法产物——code-review 的 `[impl-review-fix]` 会合法修订 design.md（措辞）/tasks.md（勾选回填）并打 `checkpoint(impl-review)`。

**修复方案**（ship-gate-hardening design D2）：
- `is_stale` design 域改为分帧遍历 `git log --name-only`，对 subject **精确匹配** `== "checkpoint(impl-review)"` 或 `startswith("checkpoint(impl-review):")` 的帧豁免其对四件套的改动；精确式（非前缀模糊）防 `checkpoint(impl-review)evil` 尾串伪豁免。锚测 `test_impl_review_exempt_bare_and_colon` / `_evil_suffix_stale` / 空 subject / 交错帧。

**影响范围**：仅 design-approved 新鲜度判定。**已知边界**：豁免凭 subject 前缀而非改动类型（设计门 Q2 维持现取舍，属约定级安全边界，见 ship_gate.py 头注释「已知不覆盖」）。

| 属性 | 值 |

**现象**：sdflow-done 归档+merge 完成后重跑 gate：change 目录已在 openspec/changes/archive/2026-07-04-*/，gate 按 active 路径找 spec-review-report.md 找不到 → REFUSE_START；正确语义应为检测 archive 目录存在 + merge 已发生 → SHIPPED

**修复方案**（ship-gate-hardening design D3 + 硬化 H1-H6）：

**影响范围**：仅归档后 gate 重跑语义。**已知不覆盖**：evil-merge、精确同名旧档、伪造 subject（已声明接受项）。
