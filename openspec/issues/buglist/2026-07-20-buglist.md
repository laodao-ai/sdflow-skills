## B19: code 域失鲜判据仍走 git log --name-only ⇒ evil-merge 漏检（fail-open，代码审后的改动被判 fresh）
> code 域失鲜判据仍走 git log --name-only ⇒ evil-merge 漏检（fail-open，代码审后的改动被判 fresh）

**关联文档**：`openspec/changes/fix-design-gate-freshness-proxy/design.md`

**现象**：冷层 code-review 复审隔离构造实测：两个 parent 的普通提交只碰 openspec/、merge 提交自身改 src.py ⇒ is_stale(root, rel, 'code', change) 返回 (False,'fresh')——即代码审拍板后的源码改动被判新鲜、可随档 ship。复现：两分支各提交只碰 openspec/ 的普通提交 → merge 时手工把 src.py 改掉 → is_stale(..., scope='code') 返回 fresh。

**根因**：与 design 域刚修的 F1-a 同源：git log --name-only 对 merge 提交不输出任何文件 ⇒ 整帧被跳过。design 域已改为 git diff-tree -m -r --raw --no-renames -z --root 修复，code 域未改。

**修复方案**：
把 design 域已验证的枚举协议（diff-tree -m -r --raw --no-renames -z --root）同样应用到 code 域。**未在本 change 内修**：design.md 的 Non-Goals 明写「改动 code 域失鲜判据（本 change 只动 design 域）」，阶段三无人类门管的是修复与裁决、不含推翻已批准的设计边界。按基准 3（面治）应在下一个 change 与本次枚举协议一并治。

**影响范围**：代码审拍板后经 merge 提交引入的源码改动不判失鲜，可绕过二次审查随档 ship。
> 2026-07-20 状态：OPEN → PROPOSED
> 2026-08-02 状态：PROPOSED → FIXED（ship_gate.py L935-956 code 域失鲜 ls-tree 内容映射比较 commit c99f677）

## B20: git 二进制缺失时 FileNotFoundError 逸出，退出码脱离契约集 {0,3,4,5,6}
> git 二进制缺失时 FileNotFoundError 逸出，退出码脱离契约集 {0,3,4,5,6}

**关联文档**：`openspec/changes/fix-design-gate-freshness-proxy/design.md`

**现象**：PATH 下无 git 时 run_git/run_git_rc/run_git_bytes 的 subprocess.run 抛 FileNotFoundError，一路冒泡出 decide()/main()，退出码变成 Python 默认的 1——而 1 不在 gate 的契约退出码集内，调用方（sdflow-ship 链序）会误解语义。对抗镜以 PATH=/nonexistent 实测复现异常类型。

**根因**：全文件级：所有 run_git* 系列均未捕获 FileNotFoundError；decide() 顶部的 git 可用性 preflight 也走同一条无防护路径。

**修复方案**：
run_git* 系列统一捕获 FileNotFoundError，映射到 UNKNOWN(6)。非本 change diff 引入（既有缺口），冷层 code-review 顺带指出。

**影响范围**：环境异常时 gate 以未定义退出码失败，链序误判。
> 2026-07-20 状态：OPEN → PROPOSED
> 2026-08-02 状态：PROPOSED → FIXED（ship_gate.py L393-421 _git_run OSError→GateIndeterminate(CAUSE_GIT_UNAVAILABLE)）
