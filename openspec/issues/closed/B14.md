## B14: 高频×多类型混合信号风暴可整体击穿 bash trap 机制，孤儿必然产生（实测 67%）
> 高频×多类型混合信号风暴可整体击穿 bash trap 机制，孤儿必然产生（实测 67%）

**关联文档**：`openspec/changes/fix-mechanical-layer-silent-failures/design.md`

**现象**：对抗镜 A 实测（macOS，真 GNU timeout）：3 秒内以 20–150ms 随机间隔【交替】发送 TERM/INT/HUP（对应现实场景：调用方 Ctrl-C 连按、CI 取消与超时同时触发），15 次独立运行中 10 次（67%）helper 被信号【默认处置】直接终止——returncode 为负（-15/-1），stderr 完全没有 ov_cleanup 的『收到 X』痕迹，即 trap 整个没跑；验尸确认 runner 与孙进程双双存活成孤儿，OV_WORKDIR 部分未清。

对照组（已排除干扰）：单一信号类型同频洪泛 0/10 复现，全部 rc=143 干净退出；慢速多类型信号会触发 trap 重入，但 M5 的原子快照+幂等设计扛得住、不产孤儿。⇒ 引爆点是『高频 × 多类型』的交集。

与 design.md 已登记残余 (a)(b)(c) 性质不同：那三条是单指令级窗口、概率极低、只影响那一次信号；这条是整条 trap 机制在信号交付层面被压垮。已登记为 design.md D2.2 的 (d*)，回归用例 test_mixed_high_frequency_signal_storm_can_defeat_trap_mechanism（概率性，不复现时 skip 并在 skip 文案警告勿删）。

**根因**：分两层，**第二层才是本条的要害**。

**第一层——孤儿是怎么产生的（Unix 语义，非本仓特有）**：helper 起的进程树是
`helper → timeout -k 10 <T> → <runner>`。父进程死掉**不会**连带杀死子进程——内核把孤儿 **reparent 到 PID 1**（launchd/init）继续跑。
立项时实测的原始现场：`42998  1  timeout -k 10 60 sleep 45`（**ppid 已变成 1**）。
∴ helper 必须**主动**在退出前杀掉 runner，这正是 R2 与 trap 机制存在的理由。

**第二层——本条为什么 trap 救不了**：trap 是「helper 主动杀」的唯一挂载点，而**高频 × 多类型信号会让 trap 整个不执行**——
helper 被信号的**默认处置**直接终止（`returncode` 为负 = 被信号杀死，而非自身 `exit`），
`ov_cleanup` 一行都没跑（stderr 无任何『收到 X』痕迹）⇒ 主动杀的动作从未发生 ⇒ 回到第一层的默认结局：孤儿。
观测到的是**信号交付层面**的失效（bash 对连续到达的**不同**信号的排队/合并处理在某个比例下整体丢弃后续 trap 调用），
具体内部机制未深挖（超出本轮时间预算），但现象稳定可复现。

**为什么这不只是「难看」——三条实际后果**：
1. **白烧 API 额度**：孤儿 runner 继续与模型对话直到跑满内层超时；调用方已取消这次评审，账单照记。
2. **脱离 harness 回收域**：harness 只管得住自己起的进程树，一旦 reparent 到 PID 1 就**再也够不着**——关终端、关 Claude Code 都不影响它继续跑。
3. **会堆积，非一次性**：每取消一次评审漏一个。**实证**：代码审对抗镜 C 在做变异验证时跑了修复前的回滚版本，
   **当场在开发机上留下 16 个孤儿 `sleep 300`**（该镜自行清理并在报告中登记）——这同时反证了 R2 要解决的问题是真实的，不是纸面声称。

**修复方案**：
属【设计级】决策，MUST NOT 在代码审里就地换机制：候选方向 (a) 外层监督者对同一信号去抖/幂等重试，需评估会不会吞掉合法的连续信号；(b) helper 内用 flock / PID 文件做单实例互斥兜底，不再把 bash trap 当唯一回收原语，需评估新引入的死锁/饿死面。两者都要重新拍 R2 的实现机制 ⇒ 应另开一个设计级 change 走完整评审。

**影响范围**：R2『父被回收时 runner 子进程必死』与 Success Metric 2『孤儿 runner 进程数 = 0』在混合信号风暴下实测不达成（单信号路径实测达成）。后果是孤儿 runner 继续烧 API 额度且脱离 harness 回收域。67% 复现率不允许被描述为『极少见』。
