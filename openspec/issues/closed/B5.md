## B5: 契约测试对 fenced 示例锚过严致既存红

| 属性 | 值 |
|------|------|
| 模块 | `sdflow-ship/tests/test_gate_anchor_scope.py` |
| 优先级 | P3 |
| 状态 | FIXED |

**关联文档**：`openspec/changes/workflow-metrics-loop/design.md`

**现象**：test_contract_archived_corpus_anchor_hits 既存红(main 亦红,非本change):归档报告 ship-gate 锚在 fenced 示例块内→子串命中但行级不命中,断言过严

**根因**：测试契约本身错——`test_contract_archived_corpus_anchor_hits` 用「子串出现（`anc in text`）」当「该报告带真 gate 锚」的 ground-truth，再断言 `_line_scoped_hits` 也命中。但报告正文会把锚串作为**讨论对象** inline 提及，那类提及本就不该被 fence-aware 独占行判据计入 →「子串命中 ∧ 行级不命中」→ 误红。「提及」与「标记」只有 `_line_scoped_hits` 能区分，拿子串去交叉校验它天生不自洽必误红。**订正原假设**：现象栏原写「fenced 示例块内」，实证占位是 **prose-inline**（`2026-07-05-gate-checkpoint-hardening/verify-report.md` L21，表格单元里讨论"锚模板独占裸行"，锚串内联于句中），非 fence——故"strip fence"一行修法不管用。

**修复方案**：改为**聚合不变量**——不再逐处断言「每个子串出现都行级命中」，改为断言「归档语料里 gate 真读的关键锚（design-approved / verify=PASS|FAIL）各至少一篇以**独占裸行**承载」。对 inline/fenced 提及免疫，同时保留真回归信号（某模板若全局去独占行，聚合集里该锚会消失）。落 `sdflow-ship/tests/test_gate_anchor_scope.py`。

**影响范围**：仅测试文件（`test_gate_anchor_scope.py` 单个函数），不动 `ship_gate.py` 生产判据（`_line_scoped_hits` fence-aware 行为本就正确）。全套件原 1 failed → 0 failed（480 passed）。
