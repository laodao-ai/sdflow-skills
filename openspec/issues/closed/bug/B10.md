## B10: helper 被 SIGTERM 回收时 runner 子进程 reparent 到 PID1 存活，脱离 harness 回收域跑满内层超时
> helper 被 SIGTERM 回收时 runner 子进程 reparent 到 PID1 存活，脱离 harness 回收域跑满内层超时

**关联文档**：`openspec/changes/async-outside-voice/design.md`

**现象**：对抗镜实测：outside-voice.sh 被 SIGTERM 后 EXIT trap 清掉 workdir，但 `timeout -k 10 <T> claude -p …` 子进程存活并 reparent 到 PID 1（实测 `39014 1 timeout -k 10 60 sleep 45`，父 shell 已死）。

**根因**：旧版 trap EXIT 只清 workdir 不杀子进程；runner 进程在父 shell 死后 reparent 到 PID 1，脱离 harness 回收域。

**修复方案**：
- `ov_cleanup()` 先 TERM、宽限 ~1s、再 KILL 兜底
- `_ov_group_kill_decision()` + `_ov_pgid_of()` 组级 KILL 守卫（D2.1），利用 timeout 既有独立进程组穿透子树
- runner 改后台执行 + 记 PID + wait，使 trap 有 PID 可杀

**影响范围**：主路径已修。残余 4 个 shell 层不可消除的窗口已诚实登记：(a) SIGKILL 时 trap 不执行；(b) `&` 与 `$!` 之间信号窗口；(c) wait 返回与 PID 清零之间信号窗口；(d*) 高频混合信号风暴整体击穿 trap 机制
