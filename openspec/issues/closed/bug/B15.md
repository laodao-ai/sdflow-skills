## B15: 跨进程根分裂时 recorder_lock 静默写进错误的仓根（spec R2 Scenario 3 的 MUST 当前不成立）
> 跨进程根分裂时 recorder_lock 静默写进错误的仓根（spec R2 Scenario 3 的 MUST 当前不成立）

**关联文档**：`openspec/changes/harden-repo-root-fail-closed/design.md`

**现象**：父进程 recorder_lock(inner,'sweep') 持锁 → 删 inner/.git → 子进程 issues.py --root inner reindex：rc=0、stderr 空、静默写出 outer/openspec/issues/INDEX.md。双向独立复现（implementer + Spec 轴各一次）。根因：validate_recorder_participant 抛 RecorderLockError 被 except 吞掉、回落 owner 模式（issues.py:194 / buglist.py:207 / todolist.py:207）；同根场景下是 O_EXCL 撞锁才碰巧响亮，根一分裂锁路径也分裂。爆炸半径非边角——issues.py 有 6 处生产代码以 --root 拉子进程（:1349 / :1824 / :2298 / :2315 / :2334 / :2342，sweep / auto-reindex / batch add / per-type）。已落 xfail(strict=True) 机械锚，堵上即 XPASS 判红。修法（Spec 轴给出，非结构性死结）：新增 SDFLOW_RECORDER_LOCK_ROOT，由 recorder_child_env 下传父进程 realpath，recorder_lock 判『变量存在且 != 本进程解析根 ⇒ 响亮失败』；变量缺失仍走既有回落 ⇒ 契约测试 test_invalid_participant_env_falls_back_to_owner_or_conflict 原样绿。代价：三份同步 + AST 镜像 + 触 lock spec ⇒ 须走设计门，故未在本 change 内 fold（改 spec 会令已拍板的设计门失鲜、gate 当场 REFUSE_START）
