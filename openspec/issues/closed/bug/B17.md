## B17: 回落到「非仓库且不可写」目录时仍是裸 Traceback + rc=1：makedirs 抛 OSError，main() 只 except ValueError 接不住
> 回落到「非仓库且不可写」目录时仍是裸 Traceback + rc=1：makedirs 抛 OSError，main() 只 except ValueError 接不住

**关联文档**：`openspec/changes/harden-repo-root-fail-closed/design.md`

**现象**：mkdir /tmp/ro && chmod 555 /tmp/ro && cd /tmp/ro && python3 sdflow-buglist/scripts/buglist.py next-id ⇒ stderr 吐 PermissionError 裸 Traceback、rc=1（三份 recorder 全复现）。cr-fix1 实测复核仍在。

**根因**：repo_root 在此**正确地**回落（自 /tmp/ro 上溯一层 .git marker 都没有 ⇒ 真·非 git 仓库，按 cr-fix1 的判据本就该回落）。问题出在回落之后：回落值被 recorder_lock 拿去 makedirs 建 openspec/，只读目录上抛 PermissionError(OSError)，而 main() 的兜底只 `except ValueError` ⇒ 接不住 ⇒ 裸 Traceback。即「回落值证明了是绝对路径，但没证明是个**该写/能写**的地方」的下半段。

**修复方案**：
在 makedirs / recorder_lock 层把 OSError 转成带 ERROR/cause/fix 三元组的 ValueError（与 repo_root 同款诊断格式），由 main() 既有的 except ValueError 统一收口。

**MUST NOT 把可写性判断塞回 repo_root**：next-id / scan 是**只读**命令，在只读目录下读取是合法用法，repo_root 加可写性门会把它们一起误伤——repo_root 的职责是**解析**仓根，不是**授权**写入。

**影响范围**：所有 recorder 命令在「非 git 仓库 + 目录不可写」的组合下失去受控失败形态。cr-fix1 已覆盖的是**仓内**那半（git 拒答 ⇒ fail-closed，见 test_git_refusing_inside_repo_fails_closed）；本条是 repo_root 之外的另一半，超出 cr-fix1 的改动面（只改 repo_root + tests + pytest.ini + workflows）。
