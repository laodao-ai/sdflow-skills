# workflow 成本优化 讨论备忘（memo · 考古 footage）

> 粗糙是正常形态。四件套不引用本文件（规则 3）。记录「为什么」的形成过程，防 /clear 蒸发。

## 讨论如何走到这里（2026-07-06，一 session）

1. **起点**：从 consolidation-plan 继续下一批 → 用户问「G1+G2 一起做?」→ 我按 fold-vs-defer AND 门拦下（不同 capability、零耦合、15 项过大）。
2. **升维**：用户连问「G3?」「处理后对开发循环有帮助?」→ 引出「让 workflow 深度随复杂度/清晰度自适应」的设想 → 开 change `adaptive-workflow-routing`。
3. **grill**：8 个决策 D1-D8（HR-TG 四分之一/grill不可自动跳/四谓词+known-pattern双来源/code-review两层切/掏L2判断层/route.py三层归口…）。我+用户协作收敛，自认严密。
4. **spec-review 打脸（关键转折）**：4 个独立冷源（对抗×2+接地+codex）抓出 grill **没抓到的地基级问题**：
   - **时序矛盾**：谓词 diff 派生，但路由在 diff 前（ff/grill）→ 主收益机判不可达。
   - **HR-TG 不可脚本化**：成员是语义触发（DB迁移/信任边界/并发），今天由模型判、非脚本。
   - **门核正交**：只防作者撒谎、不防脚本自漏判（共谋放过）。
   - **calibrator 幸存者偏差**：LIGHT 漏的 bug 最不可能被独立发现、从不进 buglist。
   - **ROI 抽空**：招牌收益被 grill 自己的 D4/D6 决策抽掉 2/3。
   - **本 repo markdown=行为**：改 SKILL.md 一行=「仅动 markdown」→ 误免。
5. **设计门 Q1=A**：用户拍板收敛——砍前向大机制，只留「code-review 入口无逻辑面白名单免 Step2」。
6. **换角度问成本**：用户问「时间能不能降?」→ 引出 Leg2（机械镜快档/接地镜流水线/后台）。又问「扩大 change scope 摊薄?」→ 引出 Leg3（相关合批 + 大扫除批 + 正交批边界）。
7. **收敛贯穿洞察**：成本优化边界 = **逻辑面有无**。琐碎的怎么省都行；有逻辑的省不了、只能摊薄+提速。三腿成型 → 本 roadmap。

## 几个「为什么这样、不那样」的关键推理

- **为什么 A 活下来、原方案死**：原方案要「在实现前、用脚本、判语义复杂度」——这三件凑不到一起。A 把省限定在唯一三者都成立的角落：实现后（diff 在）× 结构零产出形状（可机判）× 免之可证无损。
- **为什么独立冷镜不能跳（本 change 自证）**：本 change 试图让评审层可跳，却正是独立冷审（尤其 codex 跨模型）救了它——grill 是「我+用户协作收敛」，缺真正独立的冷眼。这是「降成本 MUST NOT 砍安全」红线的活证据。
- **为什么正交批危险、相关批安全**：正交批把镜子注意力切到多个无关子系统→稀释（刚在聚焦 change 上都差点漏）；相关批反而让镜子看到相互作用、审得更连贯。
- **codex 独立贡献 2 条**（平凡声明无 ff 入口 + buglist 无逃逸字段）——跨模型非冗余的实证。
