# 触发词目录（Trigger Catalog）

> **定位**：spec 工作流中所有「按变更内容条件触发」的**单一权威源**。
> 同一批触发词同时驱动四层：**D 约束注入 · 领域清单选用 · 画图要求 · 模版必填槽**。
> 各层只引用触发 ID（`TG-NN`），不复制触发定义——改触发只改本文件。项目无关。

---

## 一、怎么用

```
                    ┌──────────────────────────────┐
   起手对变更评估 → │   本目录（Trigger Catalog）   │
   一次,逐条判命中  │   TG-01 DB迁移  TG-05 状态机…  │
                    └───────────────┬──────────────┘
            ┌──────────┬────────────┼───────────┬────────────┐
            ▼          ▼            ▼           ▼            ▼
         D 约束注入   领域清单      画哪些图     模版必填槽   (未来层)
       ff-generation  domains/    design-diagrams spec-checklists
```

命中一个触发 → 它在四列里激活的项**同时生效**。
例：命中 **TG-01（DB 迁移）** → 自动 { 注入 D-2 + 过 backend 的 DB 段 + design 出现 `v_old/v_new 对照表` 槽 }。

## 二、无条件必填（不依赖触发，每份 spec 都要）

这些不是触发项，是恒定骨架，列此备查：

```
  proposal.md : 问题/动机 · 成功指标(Success Metrics) · 不在本次范围 · 合规声明(可"不适用")
  design.md   : 规则/边界合规声明
  specs/*.md  : 每个 Requirement 挂 #### Scenario(WHEN/THEN) · Requirement 稳定 ID · ADDED/MODIFIED/REMOVED 分组
  tasks.md    : 任务 ↔ 需求 ID 双向追溯
```

## 四、四层消费方（各层如何引用本目录）

| 层 | 文件 | 引用方式 |
|----|------|---------|
| D 约束 | `ff-generation-constraints.md` | D-2/D-4/D-6 的触发条件即 TG-04/08/06 |
| 领域清单 | `spec-checklists/`（设计期 autoplan）+ `code-checklists/`（代码期 /review） | 同一 TG-01/02/03 选 domain，两份清单同源；设计审过 spec-checklists/domains，代码审过 code-checklists/domains |
| 画图 | `design-diagrams.md` | 触发条件表即 TG-09~14、TG-18 |
| 模版槽 | `spec-checklists/`（base/domain T 项）+ 模版骨架 | 每个 `〔触发〕` 槽标注对应 TG-NN |

## 五、扩展约定

1. 新增触发 → 取新 ID（`TG-NN`，按类别归到 A~G），ID 不复用、不重排。
2. 填四列：该触发激活哪些 D约束 / 领域 / 画图 / 模版槽。
3. 在对应消费方（ff/domains/diagrams/模版）用 `TG-NN` 引用，**不复制触发定义**。
4. 删除触发只留空号，更新所有引用方。
