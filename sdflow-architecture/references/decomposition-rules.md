# 子系统拆分规则集：R1–R11 + 反模式黑名单 AP1–AP4

> **真相源=本文件**；蓝本 `docs/sad/02-architecture-skill-design.md` §5.1/§5.2 已冻结为设计考古层，不再更新——后续修订判据/反模式一律改本文件，不回改蓝本。
> 来源标注：Parnas 1972 信息隐藏 / Evans DDD / Newman / Skelton-Pais / Löwy / Nygard；四判据推导过程记录在 `docs/sad/00-*.md` Q1 结论（考古层），此处为完整可执行规则。

## Phase A：生成候选（从需求到候选清单）

### R1 原料提取

从需求 + 问卷答案提取四类原料：**用例清单**（系统要响应的事件/要做的事，动词短语）、**领域名词**、**外部接口**（十节骨架第 3 节）、**数据类别**（持久数据 + 运行态）。这是轻量版 event-storming——不开工作坊，AI 枚举 + 人补漏。

### R2 语义聚类成候选

按领域语言聚类——同一词汇圈的用例+数据 = 一个候选子系统；每个候选先给**一句话职责**。候选数量此阶段不设限，进 Phase B 前粗合并到 ≤9。

### R3 物理边界先行

部署/进程/二进制边界（来自骨架第 7 节与约束）是**硬切分**——跨进程/跨网络处必有子系统边界（反之不然：同进程内仍可多子系统）。**技术分层不是子系统**（见 AP3）；域概念被物理边界劈开时（如同一概念在前端+后端各有一半），两侧以 contract 缝合、**命名强制对齐**（防语言漂移）。

## Phase B：四判据精修（对候选清单迭代执行）

### R4 变化率检验

列**预期变化清单**（类别 checklist：需求功能方向 / 外部协议与依赖版本 / 技术选型替换 / 规模与性能 / UI 形态 / 合规——载体：`references/checklists/change-categories.md`）。逐条标注击中几个候选：**击中 ≥2 → 边界疑点**，按序三选一（**根治优先，顺序即优先级**）：①移动职责（根治）→ ②判定该变化属横切、归骨架第 8 节（重新定性）→ ③显式接受并记 ADR（显式债务）——不许跳到③图省事。

### R5 单写者检验

每类数据（含运行态）标唯一 writer；出现双写 → 边界错，重新分派所有权。

### R6 context 预算检验（硬约束）

估算每个候选「完整设计 + 自身 contract + 邻居 contract 摘要」的体量；**超预算 → 必须再切或收窄职责**；远低于预算且与某邻居高内聚 → 考虑合并（防碎片化）。

### R7 依赖形状检验

画候选间依赖图。**环 → 违规必须解**（提取公共下层 / 翻转依赖）；**hub**（一个候选与全部相连）→ 疑点：要么它是真核心域（记 ADR 显式接受），要么职责过宽（按语义簇拆）。

## Phase C：仲裁与终止

### R8 冲突仲裁序

判据打架时，按序仲裁：

1. **context 预算 + 依赖无环是硬约束**——必须满足，无豁免；
2. **语言边界默认保持**——两个语义域高共变时，优先解释为「contract 缺了抽象」（修 contract），**而非合并两个语义域**（合并污染语言，代价更高、不可逆）。**后验兜底**：修完 contract 后若后验仪器回检**仍**高共变 → 承认语言边界误判（本是一个域被误拆为二），此时合并是对的——语言优先是**第一响应，非永久豁免**；
3. 同一语义域内出现**独立变化簇** → 记为该子系统的 L2 内部模块候选，**不升子系统**（那是步骤二 scope）；
4. **改动成本不进 SAD 期仲裁**——SAD 期是边界决策的**免费窗口**（纸上重切零成本，代码里重切昂贵），此时按 1–3 把边界做对；成本仲裁仅在存量迁移场景进场且**排最后**（先判根治、再锚目标态、最后才计成本）。存量项目的现状代码结构只是证据、**不是判据输入**。

### R9 粒度带与终止

目标 **3–7 个**子系统（超出 → 合并低风险相邻域；不足 3 且单体超 context 预算 → 再切）。一个子系统 = 一个 agent 一个 context 吃得下的设计单元。到粒度带且 R4–R7 通过 → **停止**，不做子系统内部细分。

**统一原理：边界贵、内部便宜**——每条子系统边界 = contract + 集成 + 评审 + 文档的固定协调成本，内部结构改动自由。口号：**子系统边界往上合、内部模块往下拆**（与 change 拆分标准「change 边界往上合、内部粒度往下拆」同源，两轴共用同一条经济学；「别为小职责开新子系统」与「相关项 fold 进当前 change」也是同一防碎片化逻辑）。

> **定稿增量（带宽外留痕）**：最终子系统数落在 3–7 带宽**之外**（即 <3 或 >7，且已按 R9 尝试合并/再切仍无法回到带宽内）→ **须在 ADR 记一句理由**，说明为何本系统偏离粒度带（例：域天然只有 2 个强内聚部分、或规模巨大需 >7 个）。不允许静默带外，也不允许把「带外」直接当默认解——ADR 理由是最后一道留痕，防止「切不动就算了」。

### R10 拆分做全景、实施做增量

SAD 一次把**空间切全**——含后期阶段才实现的子系统（边界 + contract 占位，成熟度标 `planned`），**不许**因「阶段 N 才做」而不划边界；实现缺位的依赖 = contract-only 占位 + todo 登记（与骨架先行同构：contract 先行，实现后补）。空间一次切全，时间分期填充。

### R11 留痕与输出 schema

拆分判据、被否切法、显式接受的疑点（hub/横跨变化）→ **第一条 ADR**。每个子系统按固定 schema 落盘（= 原始三要素的字段化）：

| 字段 | 内容 |
|---|---|
| 目标 | 一句话职责（R2 产出，精修后） |
| 范围 | owns 的用例清单 + owns 的数据（R5 写权矩阵行） |
| 边界 | 明确**不做**什么（与邻居的分界句） |
| 对外 contract | 清单，骨架前只填主干三层（语法/所有权/错误语义归属），带成熟度标签 |
| 注意事项 | 指向横切概念（第 8 节条目引用）+ 风险登记（第 9 节条目引用），**不自由发挥散文** |

## 两轴正交提醒（定稿增量①）

本规则集切**空间**（R 轴：子系统边界怎么切）；change/task 切**时间**（AP 轴之外的另一维度：交付单元）。feature/change 垂直穿多个子系统是**正常且推荐**的（tracer bullet 即此形态）——「一个 change 一个完整结果」**不等于**「一个 feature 独占一个子系统」。子系统的内聚单位是**职责与变化原因**，不是交付单元。

> 两轴对照：**R 轴**（R1–R11）回答「怎么切空间」——子系统边界画在哪；**AP 轴**（AP1–AP4，见下）回答「什么形态不许出现」——反模式黑名单是对 R 轴产出的负面清单校验，两轴正交、不可互相替代（R 轴合规 ≠ 未落入 AP 反模式，两边都要过）。

## 反模式黑名单 AP1–AP4

> AI 推荐步**必须先自检再交人**——AI 自由分解的默认输出 = AP1/2/3 高发。

**AP 自检留痕格式（定稿增量②）**：候选切法命中任一 AP → 必须记录以下三行结构化字段（修正前/后切法对比，便于人门快速核验「真改了还是嘴上说改了」）：

```
before: <自检前候选切法一句话，含被判定命中 AP 的具体子系统名/职责描述>
after: <修正后切法一句话>
触发 AP 编号: AP<n>
```

未命中任何 AP 的候选无需填写本格式；候选被 AP 规则毙掉后仍保留（体内删除线或附录），充当 ADR「被否切法」栏。

### AP1 entity-service（按名词切）

识别特征：子系统名 = 数据实体名（User/Order/Device）；任一用例都要穿 ≥3 个子系统。
修正动作：按用例/能力重新聚类。

### AP2 流程式分解（按步骤切）

识别特征：子系统名 = 处理阶段（接收/解析/处理/输出）；数据一路穿过全链；任何需求变化击中全链。
修正动作：按变化原因重新聚类。

### AP3 技术分层当子系统

识别特征：切出来是「UI 层/业务层/存储层」。
修正动作：层是子系统内部结构或横切约定；子系统按领域垂直切（物理边界除外，见 R3）。

### AP4 God-hub

识别特征：一个子系统与所有人高耦合；职责描述要用「和」连 ≥3 个名词。
修正动作：按语义簇拆；或确属核心域 → ADR 显式接受留痕。

## 候选分解的数量规则

候选数**不定配额，由仲裁分歧数驱动**：

- R8 仲裁出现**真实分歧**（如语言边界 vs 变化率打架、hub 拆不拆）→ 每个分歧点生成一对真实候选（整体通常收敛为 2–3 个方案）——分歧点即分叉点，天然不是稻草人；
- 四判据**无分歧** → 允许单方案直出，**MUST 显式声明一行**「判据无分歧，单方案直出」（跳过类判定显著呈现）；黑名单自检中被 AP 规则毙掉的形态充当 ADR「被否切法」栏，三件套仍填得满；
- **禁止凑数**：候选必须源于真实判据分歧，不许构造明显劣化的对照方案——稻草人让拍板变表演（假绿近亲），比单方案更糟。
