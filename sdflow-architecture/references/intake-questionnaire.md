# 事实类三问（intake questionnaire）

> **真相源=本文件**；蓝本 `docs/sad/02-sad-skill-design.md` §5.3（D3 结论）已冻结为设计考古层，不再更新——修订一律改本文件。
> 本文件只含三问 + 各问的追问提示；**不含价值类问题**（见下方声明）。

## 三问全文

问卷 = 事实类三问（**必答**，任一缺 → 锁 draft）：

### ① 一句话定位

是什么 / 给谁用 / 解决什么问题。

**追问提示**：若答案里出现多个不同角色或多个互不相关的问题域，追问「这是给单一角色/单一场景服务，还是要覆盖多个不同使用场景？」——防止「一句话定位」实为多个产品合并成一句话，掩盖了本该拆成多个 SAD 的信号。

### ② 外部系统清单 + 文档指针

外部系统清单，**含文档指针追问**（引导证据指针，非空谈清单）。

**追问提示**：逐个外部系统追问「是否有可用的协议/接口文档？指向哪里（URL / 内部 wiki / 无文档只能问对接方）？」——文档指针缺失本身要显式登记（`[假设]` 标记），不能因「说不出指针」就跳过该外部系统。若答不出「还有哪些外部系统」，可提示 `checklists/external-deps-typical.md` 的典型集协助枚举（云服务/DB/消息/固件外设/第三方 API）。

### ③ 硬约束（五分项）

栈 / 平台 / 部署形态 / 必须兼容的存量 / 合规红线。部署形态并入本问为 R3 物理边界供料，**不开第七类**。

**各分项追问提示**：

- **栈**：现有技术栈是否强制延续？是否有明确禁用的技术？
- **平台**：目标运行平台（云 / 端 / 嵌入式 / 移动）？
- **部署形态**：单机 / 分布式 / 多进程？（供 `decomposition-rules.md` R3 物理边界判据）
- **存量**：是否有必须兼容的现有系统 / 协议 / 数据格式？
- **合规**：是否有行业或法规红线（数据本地化、审计留痕、隐私分级等）？

任何项目 owner 五分钟可答完。

## 价值类问题 MUST NOT 进首轮

质量取舍 / 风险承受度 / Non-goals **后置到拍板阶段**，挂具体产物以选择题形态问（「A/B 切法选哪个」优于「描述你的质量取舍」一个量级）——**事实前置、价值后置**：day 0 不仅不逼人答抽象问题，**连问都不问**，等有具体产物再问。首轮采集**仅**含上述三问，价值类问题出现在首轮问卷中即视为设计违规。

## 允许「不知道」

任一问缺答 → **锁 draft**，但这是合法的非阻塞状态，不是流程失败：

- 缺答本身要显式记录（而非静默略过），产物停在 draft 态直至补齐；
- 不阻塞继续采集其他信息或产出草案——draft 态允许推进后续步骤（推荐/草稿生成），只是不允许升到 `skeleton-ready`；
- 「答不出」与「没问」需可区分：追问提示已给过、owner 仍答不出 → 记为待补事实项，而非视为该问未问。
