## SAD 边界总则（元判据：X 该不该进 SAD）

S1–S11 判「进了 SAD 的内容好不好」；本总则判**该不该进**——先过边界、再过判据（防 SAD 从「结构真相源」膨胀成 README+runbook+测试计划大杂烩，违 02 §0.3「刚好够」+ S11 单一真相源）。一个 X 进 SAD **当且仅当四问皆是**，否则归相邻文档、SAD 引用不复述（生态图 + 相邻文档地图见 `docs/sad/04-ecosystem-boundaries.md`）：

1. **跨子系统？** 影响 ≥2 子系统的一致性——否（单子系统内部）→ L2 子系统设计
2. **架构决策？** 在约束内选了什么结构/契约——否（操作步骤）→ README/runbook
3. **空间/当下？** 非时间排期——否（排期）→ roadmap
4. **下游 context 要携带？** 模块 agent 生成时要知道的约束——否（纯人读手册）→ CONTRIBUTING

**典型误收（起草时高发，MUST 挡）**：安装/配置**步骤**（→ README；SAD 只留 §8 配置**策略**决策）· dev/测试环境**搭建**（→ CONTRIBUTING；SAD 只留 §2 栈/平台**约束**）· 测试框架/目录/泳道**细节**（→ testing-strategy 文档；SAD 只留 §1 可测试性质量属性 + §8「测试策略」横切一行引用）· **阶段/排期**（→ roadmap；SAD 成熟度只标空间态 planned/draft/validated/frozen，不标 M 阶段）。

## 语义判据全集（S1–S11）

### S1 可裁决性

质量目标有排序有度量，两方案冲突时文档能给出裁决。

### S2 可走查性

关键场景在文档上走得通：每步定位子系统、跨界指到 contract、质量场景有满足机制。

### S3 分解正当性

划分有判据、无反模式（entity-service / 流程式）、边界与变化对齐。

### S4 contract 完备性

每条边界五层覆盖，缝隙不留给实现者自由发挥。

### S5 可追溯性

决策有 why（备选+后果）、数值有来源、假设有标记——读者能区分事实/拍板/推测。

### S6 一致性

术语统一、数值无互斥、各节不自相矛盾、不违约束。

### S7 考虑面完整性

该考虑的都考虑过：十节全覆盖或显式 N/A；「考虑过判不需要」≠「没想到」。

### S8 目标态锚定

设计锚目标态而非现状快照；不拿现状反驳目标。

### S9 风险对位

设计深度与风险分布对齐：高风险深、低风险浅。

### S10 context 可路由性

文档可切片喂给下游 agent：子系统任务包可独立抽取，无需读全文。

### S11 演进可维护性

单一真相源、引用不复述；改一处不需同步 N 处。

## 机械化拆解表：可结构化部分 vs 语义残余

| 判据 | 可结构化（确定性信号 → 脚本断言） | 语义残余 | 残余归属 |
|---|---|---|---|
| S1 | 排序存在且全序（无并列）；每条带数值度量；数值有溯源标记 | 排序反映真实优先级吗；数值合理吗 | **人门**（价值） |
| S2 | 走查矩阵存在；场景覆盖四类（主流程/故障/启停/一致性）≥各一；矩阵无空格 | 「满足机制」真能满足吗；场景选对了吗 | 评审镜 + 人补场景 |
| S3 | 分解判据 ADR 存在（按什么切+否了什么）；每子系统有变化驱动标注 | 边界与变化真对齐吗；反模式识别（启发式弱信号，判定归语义） | 评审镜；**后验共变回检**（跨期机械，见下注） |
| S4 | 每条 contract 五层字段「有内容 或 显式 N/A」 | 不变量是真不变量吗；错误语义闭合吗；还剩哪些缝 | 评审镜（对抗镜找缝） |
| S5 | ADR 三件套结构；`[假设]` 计数；数值溯源三态标记（实测/人拍/推荐待校准）覆盖率 100% | 推测依据成立吗；实测值是否真实测得（非拍板冒充） | **人门**（逐条确认假设） |
| S6 | 术语扫描（正文 vs 词汇表）；引用完整性；同量纲数值互斥比对 | 跨节隐含假设冲突 | 评审镜 |
| S7 | 十节「存在 或 N/A+理由」；横切清单逐项「已定 或 N/A」 | N/A 理由成立吗；清单外领域特有项遗漏 | 评审镜 |
| S8 | **几乎无确定性信号**（至多弱启发：否决理由含「现状/目前很少/存量没有」词面 → 只报不判） | 全部 | 评审镜专项 lens（目标态镜） |
| S9 | 风险登记存在、每条有等级+承受度字段；深度分配与风险等级联动（高风险子系统必须标 L2 深设计） | 风险评估准吗；等级定对了吗 | **人门**（承受度）+ 评审镜 |
| S10 | 每子系统切片 token 测量 ≤ 预算；切片引用闭包可机械解析 | 切片语义自足吗（agent 拿着够用吗） | 骨架期试跑验证 / 评审镜 |
| S11 | 重复段检测（双写告警）；分家落位检查（ADR 在 adr/、术语在 CONTEXT.md、SAD 只索引） | 真相源划分合理吗 | 评审镜 |

> **S3 特例注**：分解正当性在设计期近乎纯语义，但**运行期有后验机械仪器**——git 共变分析：按**逻辑变更**（非 commit——实测 commit 级口径会低估耦合约 3 倍）聚合统计模块共同被改的频率，高共变对即边界裂缝候选。属「跨期机械化」：设计期评审标注「待后验」，阶段边界回跑仪器，共变漂移 → 回流修正 SAD。
> **S8 特例注**：全集里唯一近乎纯语义的判据——这是诚实边界，不是弱点；它成为评审镜单里的专职一镜（见 `review-lenses.md` 目标态镜）。
