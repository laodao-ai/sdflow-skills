## 组件④review 工具：三份组件清单（来自 §3.3 拆解产出）

语义判据拆解（`quality-criteria.md` 机械化拆解表）的产出直接落成 skill 的三个组件（无一浪费）：

1. **「可结构化」列聚合 → 机械层脚本断言清单**（`sad_lint.py` 的需求规格）
2. **「语义残余」列聚合 → 评审镜单**（spec-review domains 的 SAD 版——每条残余就是一面镜的审查焦点，见下节）
3. **价值类残余（S1 排序 / S5 假设确认 / S9 承受度 + 拍板项）→ 人门清单**（HARD-GATE 议程）

## 机制 A：假设显影（防「幻觉架构文档」，服务 S5）

一次生成的 SAD 最危险的属性是**看起来权威**。AI 从薄需求也能产出一份完整、自洽、专业的 SAD——里面塞满了它自己编的组织事实和价值取舍。对策：

- AI 每处推测/编造 **MUST** 标 `[假设]`（含推测依据），聚合进假设清单
- 一份「看起来完整」但带 30 个未确认假设的 SAD = 30 个洞的 draft
- **文档状态机**：`draft → skeleton-ready → validated →（逐条）frozen`。skeleton-ready 门槛 = 事实类三项齐（定位/外部系统/硬约束）+ 假设逐条「显式接受 或 标待校准」；事实类关键项缺失 → **fail-closed 锁 draft**

## 机制 B：数值溯源（服务 S1/S5）

每个数（延迟预算、容量、超时……）标来源。溯源光谱（可信度由硬到软）：**实测**（可复现测量，最硬）/ **人拍**（owner 拍板的决策值）/ **域惯例推荐**（AI 给出处）/ **纯占位**（最弱）。**v1 落三态**——`〔实测〕` / `〔人拍〕` / `〔推荐待校准〕`（纯占位并入推荐态的告警清单）。fitness function 只允许长在「实测」「人拍」「推荐已校准」上。`〔实测〕`（可复现的客观测量，如基准跑分）语义独立于「人拍」（主观拍板）——审计/retro 据此区分「量出来的」与「拍出来的」，勿把实测值塞进〔人拍〕。

## 语义残余镜单（逐条带 S 编号引用）

> 每面镜 = 一个语义残余审查焦点；镜位不覆盖机械层已断言的部分（见 `quality-criteria.md` 拆解表「可结构化」列），只审残余列。

### 走查镜（S2）

场景走查矩阵「满足机制」是否真能满足质量场景；场景选对了吗（遗漏场景由本镜提名，人补场景确认）。

### 分解正当性镜（S3）

边界与变化真对齐吗；AP 反模式识别（启发式弱信号，判定归本镜，见 `decomposition-rules.md` AP1–AP4）。**后验兜底**：post-hoc git 共变分析属跨期机械仪器（非本镜单常规审查项——设计期评审只标注「待后验」，阶段边界回跑仪器，共变漂移 → 回流修正 SAD）。

### 对抗找缝镜（S4）

不变量是真不变量吗；错误语义闭合吗；contract 五层还剩哪些缝——对抗视角找机械断言够不着的隐藏缝隙。

### 一致性镜（S6）

跨节隐含假设冲突（术语扫描/数值互斥比对已机械化，本镜补语义残余：两节表面不矛盾但隐含假设互斥）。

### 考虑面完整性镜（S7）

N/A 理由成立吗（「考虑过判不需要」是否站得住）；清单外该领域特有项是否遗漏（`checklists/` 是通用集，领域特有项仍需本镜兜底）。

### 目标态镜（S8）

全集里唯一近乎纯语义的判据，**专职一镜**：设计是否锚目标态而非拿现状反驳目标；否决理由含「现状/目前很少/存量没有」词面时重点核查（机械层至多弱启发只报不判，本镜做真判定）。

### 风险对位镜（S9）

风险评估准吗、等级定对了吗（承受度归人门拍板，本镜辅助核验风险等级与设计深度分配是否联动合理）。

### 切片自足性镜（S10）

子系统切片语义是否自足，下游 agent 拿着够用吗（token 预算已机械测量，本镜判断语义完整性；骨架期试跑验证优先，评审期为辅助手段）。

### 演进可维护性镜（S11）

真相源划分合理吗（重复段检测/分家落位检查已机械化，本镜补语义判断：分家边界画得对不对）。

> **S1（排序真实性/数值合理性）与 S5（假设推测依据成立吗）不设评审镜**——两者是价值判断，直通人门（HARD-GATE 议程），见 `quality-criteria.md` 拆解表「残余归属」列。

## 走查与评审分档

**独立性三层级**（各治不同的病）：

1. **fresh context**（治生成 session 自证偏差——默认必有）
2. **跨模型 outside voice**（治**同族先验相关性**：同族模型用同一 prior 填缝，「合理但错」的假设同族审稿人同样觉得合理——升档时尽量有）
3. **人门**（治价值判断——必有）

**默认档（每次必跑）**：lint + **冷走查**（1 个 fresh Claude 子代理执行场景×子系统×contract 矩阵——**禁止生成 session 自查**）+ 人门。走查是半机械活（prior 依赖低），fresh context 已够，默认不引外部依赖。

**升档多镜**，命中信号表任一（判定显式陈述一行 + 留痕）：

1. **骨架验证慢/贵**：无法一个 change 打通（硬件依赖/外部审批链/分布式部署）——核心判据：**多镜价值 ∝ 骨架真验证的延迟与成本**，骨架快时纸面重审是浪费，骨架慢时纸面审是唯一防线；
2. **不可逆决策面大**：落盘 schema/对外发布 API/多进程拓扑（骨架也难救的错）——**`planned` 不豁免**：一旦落地即不可逆的 contract（对外发布/落盘 schema/生产副作用），即便当前标 `planned`/`draft` 也算命中本信号；SAD 层的对抗设计正是要在它落地前审，**MUST NOT 用「已 validated 过」或「planned 以后再说」消解本信号**（前者不代表 SAD 层对抗重论证已做，后者恰是落地前该多镜看的高风险项）；
3. **不可控外部 contract 多**；
4. **操作者显式要求**。

**outside voice（codex）政策**：升档多镜且 codex 可用 → **至少一面镜用跨模型**，放在 prior 依赖最强的镜位（S4 对抗找缝镜 / S8 目标态镜）；宿主探测 + 降级路径：未装/调用失败 → 退回 Claude 镜 + **显式提示不静默**。操作者显式要求时任何档可指定。

**排除项**：假设计数高 **≠** 升档信号——假设多 = 缺事实，回①补采集；多镜审不出事实缺失，只会花预算确认「这确实是假设」。
