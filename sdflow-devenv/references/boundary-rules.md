# 归属判据（归位模式：旧素材该去哪）

> **只在归位模式（brownfield）用**：项目里已经散着旧的测试/环境文档，要把它们归位。
>
> **这一步是全流程唯一无确定性信号的一步** ⇒ **人门放这里，不放末尾审文档。**

---

## 1. 切线表：每一节判去一个格

| 格 | 收什么 | 判据 |
|---|---|---|
| **`testing-strategy.md`** | **测试的一切**——选型 · 规范 · **命令怎么跑** · 装什么写什么 · 信心与盲区 | 「这句话是在说**怎么测**吗？」 |
| **`environments.md`** | **非测试**——dev 搭建（工具链 · 依赖服务 · 构建 · **常见坑**）· deploy 发布（平台 · 配置 · 流程 · **回滚**） | 「这句话是在说**怎么把它跑起来 / 发出去**吗？」 |
| **roadmap** | **时间轴**——「M2 补 e2e」「Q3 上 CI」 | 出现**阶段词面**（M1/M2/Q3/第二期） |
| **SAD** | **架构决策**——「为什么选 MQTT 而不是 gRPC」 | 在回答**「为什么是这个结构」** |
| **入口**（README / CLAUDE） | **最小命令 + 指针**——不复述 | 「新人第一眼该看到什么」 |
| **已失效** | 上面几格全搬走后，原地剩下的 | 见 §3 |

**⚠️ 最容易判错的一条：切线是「测试 vs 非测试」，不是「方法 vs 操作」。**

> 「集成测试怎么跑」——**命令**、**依赖**、**harness**，**全部归 `testing-strategy.md`**。
> **别把它劈成「方法在这份、命令在那份」**——用户想知道「集成测试怎么跑」，**不该翻两份文档自己拼**。

---

## 2. 边界四问（一段内容不知道归哪时）

1. **它在回答「怎么测」吗？** → `testing-strategy`
2. **它在回答「怎么跑起来 / 怎么发出去」吗？** → `environments`
3. **它在回答「什么时候做」吗？** → roadmap
4. **它在回答「为什么是这个结构」吗？** → SAD

**四问全否** ⇒ 它可能是**复述**（别处已有）⇒ **归「已失效」**。

---

## 3. 旧素材的三种处置（**skill 没有删除能力**）

> **`adr/0022`：skill MUST NOT 删除用户的任何文件。**
> **爆炸半径不受控**——指向它的引用可能在**仓外**（别人的书签、别的仓的文档、藏在代码注释里的路径）。
> mqtt-console 那次，旧路径藏在 `Makefile` 注释和 7 个测试文件注释里，**共 20 处——而那还只是 `grep` 得到的。**

| 处置 | skill 做什么 | 内容 | 判据 |
|---|---|---|---|
| **整体失效** | 文件**开头**加一行：<br>`> ⚠️ 已失效 —— 内容已迁至 openspec/architecture/testing-strategy.md` | **原样保留** | 范围 = 整份，**无歧义** |
| **部分失效** | **删掉失效的那部分内容**（+ 留一行指针） | **删除** | **「失效范围」必须由「它不存在了」界定**——留着内容只加标记，读者无法判断哪几行失效了。**这是最糟的中间态** |
| **真删文件** | ❌ **不做**——收尾报告给出 `git rm <file>` | 人决定 | 爆炸半径不受控 |

**一句话：skill 可以改文件里的内容，MUST NOT 删掉文件本身。**

> **看得见的双写，是一个待办；看不见的误删，是一个事故。**

---

## 4. 引用面统计（带着数字进人门）

**skill 先跑 `grep`，把数字摆出来**，然后由**人**决定要不要 `git rm`：

```
引用数 = 0         → 建议直接 git rm
引用数少（可枚举）  → 建议改掉这些引用后 git rm
引用数多 / 散      → 建议保留文件 + 顶部失效标记（别删）
```

**MUST 扫到代码注释里**——旧路径最爱藏在那儿。

---

## 5. 呈现纪律

**搬运表 MUST 先给人确认再落笔。**

**MUST 单列一节**：

```
## 以下 N 个文件建议删除（命令附后，请自行执行）

- docs/modules/testing.md        （0 处引用）  git rm docs/modules/testing.md
- docs/dev-setup.md              （3 处引用）  先改 README:12 / CONTRIBUTING:5 / Makefile:2 的注释
```

**MUST NOT 只在表格某行标个 `[删除]` 混过去**——跳过类判定别埋进长消息。

---

## 6. 归位模式最大的坑（血泪）

> **若写成「读模板 → 填文档」的生成型，模型会重写一份，而源文件原地不动 ⇒ 双写变三写。**
>
> **正确骨架**：**盘点 → 判归属 → 搬运（含标失效）→ 补空 → 反向瘦身 → 自检**
> **「盘点」和「判归属」必须真的发生，且必须先给人看。** 跳过它们直接生成，就是在制造第三份文档。
