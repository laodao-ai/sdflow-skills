# `environments.md` 提问清单 + 模版（dev 搭建 · deploy 发布）

> **与 [`testing-framework.md`](./testing-framework.md) 对称**：那份管**测试**，这份管**非测试**（怎么把它跑起来 / 怎么发出去）。
> **`SKILL.md` 第 ① 步就是在跑这份清单。**
>
> **它是「问什么」，不是「答什么」。** 答案由模型现场调研 + **人拍板**。
>
> **⚠️ 与 `testing-strategy.md` 的一个关键差异**：本文档的槽是**长自由文本**（「新人最容易卡在哪一步」「回滚怎么做」）——
> **MUST NOT 塞进 JSON 机械渲染**。把人写区强行 JSON 化，只会让人写得更烂。
> **但「有模版 + 逐槽问出口」和「有 JSON 载体」是两件事——本文档要前者，不要后者。**

---

## 0. 为什么这十槽值钱（接地实证，别跳过）

`06` 的实测：`environments` + `testing-strategy` 的 17 个槽里，**SAD 真投影只有 2 个（12%）**，其余是纯人写。

> **而纯人写区——「常见坑」「回滚怎么做」「配置项清单」——恰恰是全篇最高价值的部分。**

**这不是「生成价值低」，而是「这 88% 全是待决策项，需要有人问、有人拍、有人留痕」。**
**⇒ 这正是本 skill 存在的理由：不是替你写，是把该问的一条不落地问出来。**

**⚠️ 最容易被跳过的三槽，恰好是最贵的三槽**：**常见坑** · **回滚** · **构建副产物**。
它们没有「标准答案」，模型答不出来，只能问人——**所以最容易被静默略过。别略过。**

## §1 dev —— 怎么把它在本机跑起来

### 槽 1.1 前置工具链

**问**：

> 「一台**全新的机器**，要装哪些东西才能开始开发？—— **每一项都要有版本和安装法。**」

**判据**：

- ✅ **锚「一台干净的机器」**，不是「我这台」。
- ✅ **每项有版本**：`Go 1.22+` 不是 `Go`。**版本不写，下个人踩坑。**
- ✅ **有安装法**：`brew install go` / `asdf install`。

**反模式**：

> ❌「需要 Go 和 Node」 —— **哪个版本？怎么装？为什么是这个版本？**
> ✅「Go 1.22+（`brew install go`；1.21 不行——我们用了 `slices` 包）· Node 20 LTS（`nvm use 20`）」

---

### 槽 1.2 本地依赖服务

**问**：

> 「跑起来要连哪些**外部服务**？（broker / DB / 缓存 / 队列）**怎么起？怎么停？怎么知道它起来了？**」

**判据**：

- ✅ **起停要有命令**，不是「自己想办法起一个 mosquitto」。
- ✅ **要有「怎么知道它活着」**——`nc -z localhost 1883` / `docker compose ps`。
- ✅ **说清是「必须的」还是「可选的」**——不起它，哪些功能跑不了？

**反模式**：

> ❌「需要 MQTT broker」
> ✅「mosquitto 2.x —— `docker compose up -d broker` 起，`docker compose down` 停，`nc -z localhost 1883` 验；**不起它，`make integration` 会挂**，但纯单元测试不受影响」

---

### 槽 1.3 构建 + 本地运行

**问**：

> 「**怎么 build？怎么跑起来？**—— 给我能直接粘贴的命令。」
> 「跑起来之后，**怎么知道它真的活着**？（健康检查 / 打开哪个 URL / 看什么日志）」

**判据**：

- ✅ **命令必须为真**——skill **MUST NOT 虚构** `make dev` / `make build`。
  > 🔴 **历史陷阱**：纯文档型的 prompt 会为了对齐模板范式而**编造** `make dev/test/build`——**而项目里根本没有 Makefile**。
  > **本 skill 里这条天然成立**：命令表的出处就是 skill **自己刚跑过的那条**。**没跑过的命令，不许写进来。**

**反模式**：

> ❌「`make run`」（而项目里没有 Makefile）
> ✅「`go run ./cmd/console` —— 起在 `:8080`，打开 http://localhost:8080 应该看到消息列表」

---

### 槽 1.4 构建副产物

**问**：

> 「build 会**生成**什么？（绑定 / protobuf / 前端 dist / codegen）」
> 「**它们进 git 吗？**」
> 「**忘了重新生成会怎样？**」

**判据**：

- ✅ **这一槽是「语言桥 / 生成物契约」形态的直接体现**——如果有生成物，[`lane-patterns.md`](./lane-patterns.md) §3.3 的**结构门禁**泳道就该有。
- ✅ **「忘了重新生成会怎样」是这一槽的灵魂**——它是**最高频的、最难查的**一类 bug。

**反模式**：

> ❌ **整槽略过**（因为「感觉没什么好写的」）—— **而生成物不同步是最常见的诡异 bug 来源。**
> ✅「`make gen` 生成 `internal/pb/*.go`（**进 git**，方便 IDE 跳转）。**忘了重新生成 ⇒ 编译过、测试过、运行时字段全空**——`assert-bindings` 泳道就是为了守这个」

---

### 槽 1.5 ⭐ 常见坑（**最贵的一槽**）

**问**（这一槽 **MUST 问人**，模型答不出来）：

> 「**新人搭这个环境，最容易卡在哪一步？**」
> 「**你自己最近一次被这个环境坑到，是什么事？**」
> 「有没有那种『**看起来跑起来了，其实没有**』的情况？」

**判据**：

- ✅ **它必须是这个项目特有的**，不是通用建议。
- ✅ **每条坑要带「怎么发现」+「怎么绕」**。
- ✅ **doctor 脚本是这一槽的可执行版**——能自动查的，就写进 `make doctor`。

**反模式**：

> ❌「注意端口冲突」 —— **哪个端口？和什么冲突？怎么发现？**
> ✅「**macOS 的 AirPlay 占用 5000 端口** —— 起服务时会报一个语焉不详的 `bind: address already in use`。
>    **关掉『系统设置 → 隔空播放接收器』，或改 `PORT=5001`。**（`make doctor` 会检查这个）」

> ❌ **整槽写「暂无」** —— **一个真实项目不可能没有坑。** 写「暂无」= 这一槽没问过人。

## §3 deploy —— 怎么把它发出去

> **⚠️ 本 skill 只到「deploy 操作」为止**——**不含 on-call / SLO / 生产运维 runbook**（那是另一个层次的东西）。

### 槽 3.1 目标平台 + 依赖版本

**问**：

> 「**发到哪？**（k8s / 裸机 systemd / Lambda / 嵌入式固件 OTA / npm registry / 就是个二进制丢过去）」
> 「**目标环境上有什么？**（OS 版本 / 运行时版本 / 有没有 Docker）」

**判据**：

- ✅ **「不部署」是合法答案**（一个库 / 一个 CLI 工具）⇒ **`N/A` + 后果**（见下）。

---

### 槽 3.2 配置项清单

**问**：

> 「**跑起来要配哪些东西？**—— 每一项：**默认值是什么？不配会怎样？敏感吗？**」

**判据**：

- ✅ **每项四问**：`名字` · `默认值` · `不配会怎样` · `是不是密钥`。
- 🔴 **密钥 MUST NOT 写进文档**——只写「从哪拿」（`1Password / xxx vault`）。
- ✅ **「不配会怎样」是关键**：静默用默认值？还是启动失败？—— **静默用默认值的那些，是生产事故的温床。**

**反模式**：

> ❌「配置见 `config.yaml`」 —— **那是指针，不是清单。** 读的人还得自己去翻、自己去猜哪些是必填。
> ✅ 一张表：

| 配置项 | 默认值 | 不配会怎样 | 密钥？ |
|---|---|---|---|
| `MQTT_BROKER` | `localhost:1883` | **静默连本地**（生产上这是事故） | 否 |
| `MQTT_PASSWORD` | 无 | 启动失败 | **是**（1Password: `mqtt-prod`） |

---

### 槽 3.3 发布流程

**问**：

> 「**从「代码合进 main」到「用户用上」，中间发生了什么？**—— 一步一步说。」
> 「**哪些步骤是自动的，哪些要人点一下？**」

**判据**：

- ✅ **要能被一个没发布过的人照着做。**
- ✅ **人工步骤要标出来**——「这一步要人点 approve」。

---

### 槽 3.4 ⭐ 回滚（**第二贵的一槽**）

**问**（**MUST 问人，别让模型编**）：

> 「**发出去发现炸了，怎么退回去？**」
> 「**多久能退回去？**（30 秒？还是要重新构建 10 分钟？）」
> 「**有没有退不回去的东西？**（DB migration / 已经发出去的消息 / 已经 OTA 到设备上的固件）」

**判据**：

- 🔴 **「有没有退不回去的东西」是这一槽的灵魂。** 大多数事故不是「发错了」，是「**发错了退不回来**」。
- ✅ **给一条能直接粘贴的回滚命令。** 事故当下没人会读文档，只会复制粘贴。

**反模式**：

> ❌「回滚到上一个版本」 —— **怎么回滚？命令呢？**
> ✅「`kubectl rollout undo deploy/console`（~30 秒）。
>    **⚠️ 但 DB migration 不会自动回滚** —— 若本次发布带了 migration，先跑 `make db-rollback`，**且它只支持回退一步**。
>    **⚠️ 已 OTA 到设备的固件退不回来** —— 只能发一个新版本推上去（设备端有 A/B 分区，会自动回退到上一个能启动的镜像）」

---

### 槽 3.5 架构决策指针

**问**：

> 「为什么是这个部署形态？」—— **⚠️ 只放指针，别在这里论证。**

**判据**：

- 🔴 **架构决策的家是 SAD / ADR，不是这里。**
- ✅ 这里只写：`为什么选 k8s 而不是裸机 → openspec/adr/0007-xxx.md`

**反模式**：

> ❌ 在 `environments.md` 里写三段论证「为什么我们选 MQTT 而不是 gRPC」—— **边界失守。**

## 4. `N/A` 的纪律（与 `不适用` 同源）

**某一槽真的不适用**（一个纯算法库没有 deploy）⇒ **`N/A` MUST 连带记后果**。

| | |
|---|---|
| ✅ | **`N/A — <理由>`**，**再加一句「它留下的洞」** |
| ❌ | 只写 `N/A` |

> **只写 N/A 不写代价 = 把缺口藏进「这项不适用」。**

**例**：

> **CI：N/A** —— 本项目无 CI（个人项目，全靠本地门禁）。
> **后果**：`assert-bindings` **因此没有任何自动触发点** —— 生成物不同步只能靠人记得跑 `make gen`。
> **补偿**：`make doctor` 会检查生成物是否比 `.proto` 旧。

---

## 5. `⚠️ 待定` 的纪律（与三层框架同源）

**人当场答不上来** ⇒ **原样落 `⚠️ 待定`**，**MUST NOT 替人填**。

**收尾报告 MUST 逐条列出所有待定槽。**

> **`environments.md` 的质量没有机械兜底**——它靠**这份清单问到了**，靠**人看一眼**。
> **一个诚实的 `⚠️ 待定`，胜过一段模型编出来的、看起来很像话的废话。**（`adr/0021`）
