# 三层框架提问清单（三层 × 六槽）

> **这是本 skill 的核心承诺的唯一载体。`SKILL.md` 第 ② 步就是在跑这份清单。**
>
> **它是「问什么」，不是「答什么」。** 答案（用什么框架、用什么库、怎么跑）**MUST 由模型现场调研 + 人拍板**——工具随生态演进，固化即腐烂。
> **而问题是稳定的**：三层阶梯的道理十年不变。**固化它，是为了保证每次都问同样的十五个问题**（枚举完备性不能靠模型临场回忆——模型每次会想起不同的九个）。

---

## 0. 前置：先搞清这个项目**有哪些真实边界**

**「层」不是测试类型分类法，是保真度刻度**——**一条泳道归哪层，由「它穿过哪些真实边界」判定**，不由它用什么测试框架判定。

**所以在问三层之前，先问形态四问**（答案基本可从 SAD §3「外边界」读出；无 SAD 则问人）：

| # | 问 | 它引入的真实边界 |
|---|---|---|
| 1 | 有无**外部有状态依赖**？（broker / DB / 队列 / 缓存） | 网络 · 协议 · 持久化状态 |
| 2 | 有无 **UI**？ | 渲染 · 真 paint · 真 pointer · 真 frame timing |
| 3 | 有无**语言桥 / 生成物契约**？（FFI / 绑定 / protobuf / codegen） | **生成物文件**本身就是一条真实边界 |
| 4 | 有无**真硬件**？ | 时序 · 电气 · 烧录 |

**一个项目 = 多个形态叠加。四问全答「无」，是完全合法的**（一个纯算法库）——**那它的集成层与 e2e 层就是 `不适用`，而且那不是偷懒，是物理事实。**

**⇒ 形态决定你有哪些真实边界；边界决定泳道落在哪个刻度。**（推导框架见 [`lane-patterns.md`](./lane-patterns.md)）

## 1. 三层的判据（钉死，别再吵）

| 层 | 判据 | 一句话 |
|---|---|---|
| **单元** | **不穿任何真实外部边界**——无网络 · 无真文件 · 无真进程 · 无真依赖 | 「这个零件本身对不对」 |
| **集成** | **穿过部分真实边界**——真 broker / 真进程 / 真语言桥 / 真文件系统 / 真生成物 | 「这些零件拼起来，在真东西上还对不对」 |
| **e2e** | **端到端穿过全部真实边界**——真 UI / 真硬件 / 真部署形态 | 「用户真的用起来，对不对」 |

**⚠️ 常见误判，逐条钉住：**

| 你可能想这么归 | 正确归法 | 为什么 |
|---|---|---|
| vitest 的**组件测试** → 「组件测试算集成吧？」 | **单元层** | 它不连任何真实依赖，哪怕它渲染了 DOM。**渲染 DOM 不是穿过真实边界。** |
| 语言桥的**结构门禁**（检查导出面 / arity） → 「这不是测试吧？」 | **集成层** | 它读的是**真的生成物文件** —— **生成物契约就是一条真实边界** |
| 用 **testcontainers** 起真 DB 的测试 → 「跑在单测框架里，算单元？」 | **集成层** | 它穿过了真网络、真 DB |
| **真板烧录** | **e2e 层**，`executor: human` | |
| 用 mock broker 的测试 → 「连了 broker，算集成？」 | **单元层** | **假替身不是真实边界。** 它证明不了「消息真的穿过了 TCP」 |

> **判据只有一个：把这条测试跑起来，有没有一个「真东西」被真的碰到了？**

## 2. 六槽

**每层 MUST 答六槽。** 其中 **⑤ 不问**（它从泳道投影算出）。**所以实际要答的是 5 × 3 = 十五格。**

> **🔴 「十五格」不是「问人十五遍」。**
> **先过一遍三分判据**（SKILL.md「两条问话纪律」）：能自己查的 **MUST 自己查**，
> 查不到但有依据的 **MUST 调研后带推荐**，**只有查不到、也推不出的，才拿去问人**。

| 槽 | 问什么 | **答案在哪 / 谁答** |
|---|---|---|
| ① 本项目怎么实现 | 框架 / 库 / 工具选型 | **有代码 ⇒ 自己读**（`go.mod` / `package.json` / 现有 `_test.go`）→ 给结论人复核<br>**无代码 ⇒ 调研 → 带推荐**（P2） |
| ② 测试规范 | 写在哪 · 什么算一个用例 · 该覆盖什么不该覆盖什么 | **有代码 ⇒ 自己读**（build tag / 命名 / 目录约定）<br>**「不该覆盖什么」⇒ 模型提 → 人拍** |
| ③ 测试方法与流程 | **怎么跑（命令）** · 什么时候跑 · 谁来跑 | **自己读 + 自己跑一遍**（Makefile / npm scripts）⟹ **落成泳道** |
| ④ 需要配备的工具与脚本 | 装什么依赖 · 写什么 harness/fixture | **自己读**（compose / CI 配置 / `hack/`）⟹ **落成泳道 + 落地物** |
| ⑤ 状态 | — | ⚠️ **不问。从泳道投影算出** |
| ⑥ ⭐ **这层证明了什么 · 看不见什么** | **信心与盲区** | **🔴 查不到。** 模型读码推候选 → **人补上项目特有的那句** |

> **⭐ ①②③④ 十二格，在有代码的项目里大多是「自己查得到」的。查出来给人复核，别当问题问。**
> **省下来的注意力，全部投到 ⑥ 那三格**——**它们查不到、只能问，而且答错了整份策略就是废纸。**

> **`⚠️ 待定` 是合法答案。** 人当场答不上来（「e2e 我还没想好」）⇒ 原样落它，渲染显眼，收尾报告逐条列。
> **MUST NOT 替人填。MUST NOT 因为待定而拦住流程。**（`adr/0021`）
>
> **但 `⚠️ 待定` MUST NOT 是「我没查」的挡箭牌**：一格待定要合法，前提是**它属于第三类**（只在人脑子里）。
> 属于第一类（自己查得到）却留成待定 = **偷懒**；属于第二类（该调研）却把选项原样甩出去 = **把作业布置给了人**。

---

### 待定的两种写法（试点接地：同一份文档里，一对一错）

| | |
|---|---|
| ❌ **甩开放题** | 「⚠️ 待定：Windows 包怎么产出？（买台机器？GitHub Actions？还是 non-goal？）」——**三个选项，零调研，零推荐** |
| ✅ **调研后给推荐** | 「⚠️ 待定 —— **建议走 GH Actions windows runner**。依据：① 本仓已有 workflows ② wails 官方支持 ③ 公开仓免费。**代价**：签名要证书，首版只能出未签名包。**备选**：降为 non-goal（后果：Windows 用户没有可用产物）。**要不要这么定？**」 |

**两者都是 `⚠️ 待定`，都合法。区别是：前者把调研的活推给了人，后者只把拍板的活留给人。**

## 3. 逐槽的提问清单

### 槽① 本项目怎么实现（选型）

**问出口的话术**：

- **单元层**：「这个项目用什么写单元测试？—— 我看到的是 `<栈>`，那通常是 `<候选>`。你们有既定偏好吗，还是我调研一下给你候选？」
- **集成层**：「集成层要碰真的 `<依赖>`。它怎么起来？—— 三条常见路：**① 本机装一个**（`brew install …`）**② 容器**（compose / testcontainers）**③ 进程内真实现**（有些 broker/DB 有嵌入式版本）。你们的机器和 CI 能跑哪一种？」
- **e2e 层**：「e2e 要穿过 `<真 UI / 真硬件 / 真部署>`。**这个在你们这儿能自动化吗？** 还是只能人跑？」

**判据（模型自检）**：

- ✅ **先搜框架内置方案，再设计**——「Go 有没有内置的 httptest？」优于「我们自己写个 mock server」。
- ✅ **候选数由真实分歧驱动**：无分歧就单方案直出 + **显式声明一行**（「本项目栈明确，只给一个方案」）。**MUST NOT 凑稻草人。**
- ❌ **MUST NOT 由本清单预先钉死**任何工具。写这份清单的人不知道你的项目。

**反模式**：

> ❌「用 pytest」——**没说清「怎么起依赖」的选型，是半个答案。**
> ✅「用 pytest；broker 用 `pytest-mosquitto` fixture 起本机 mosquitto（CI 用 service container）」

---

### 槽② 测试规范

**问出口的话术**：

- 「测试写在哪？—— 跟被测代码同目录（Go 的 `_test.go`）？还是单独 `tests/` 树（Python 常见）？」
- 「**什么算一个用例？**—— 一个函数一个用例？一个行为一个用例？一个 bug 一个回归用例？」
- 「**这一层不该覆盖什么？**—— 例：单元层**不该**去测『broker 断连会不会重试』，那是集成层的活。**混进来会让单元层变慢变脆，而且它证明不了。**」

**判据**：

- ✅ **「不该覆盖什么」比「该覆盖什么」更值钱**——它是**分层正当性**的落点（能说清「为什么这条不能并进那条」）。
- ✅ 规范要**可执行**（「文件名 `*_test.go`」可执行；「写高质量的测试」不可执行）。

**反模式**：

> ❌「覆盖率 80%」—— **覆盖率不是规范，是一个数字。** 它不告诉任何人该写什么。
> ✅「每个导出函数的 happy path + 一个错误路径；每个修过的 bug 留一条回归用例（用 issue 号命名）」

---

### 槽③ 测试方法与流程（**这一槽会落成泳道**）

**问出口的话术**：

- 「**怎么跑？**—— 给我一条能跑的命令。」
- 「**什么时候跑？**—— 本地随手跑？提交前必跑？只在 CI 跑？」
- 「**谁来跑？**—— 脚本自动跑，还是人手动跑？」

**判据（关键，逐条）**：

1. **命令就是一条裸命令**——`go test -tags=integration ./internal/console/`。
   **MUST NOT 为了「显得规范」而去造一个 Makefile target**。大多数项目不需要接线。
   **只有当命令确实太复杂**（要起 broker + 设一串环境变量 + 收尾清理），才**建议**造一个 task 入口——**造在哪、叫什么，看项目现场**（Makefile / npm script / `justfile` / `hack/*.sh`）。
2. **`executor` 默认 `script`。** 「人跑」是**降级路径**，MUST 写明**为什么程序跑不了**。
   > **MUST NOT 预判「这个大概跑不了」就标 `human` 偷懒——先试着跑。**
3. **「跑不了」有两种，MUST 分清**：

   | 情形 | 落成什么 |
   |---|---|
   | **方法本身没法用程序跑**（真板烧录 · UI 视觉判断 · 需人眼看的交互） | `executor: human` |
   | **方法能跑，只是本机条件不具备**（没装 mosquitto / 没有 Docker） | `executor: script` + `blocked_by`，下次 `continue` 再跑 |

   > **把后者标成前者，是在撒谎。**「本机缺个依赖」不等于「这条只能人工验证」。

**反模式**：

> ❌「在 CI 里跑集成测试」—— **门禁只在 CI ⇒ 本地改完不知道对不对，反馈环拉到几分钟。** 而且换 CI 平台门禁就没了。
> ✅「本地 `make integration` 就能跑；CI 只是调用同一条命令」—— **本地与 CI 跑同一条命令，不会出现「CI 绿本地红」。**

---

### 槽④ 需要配备的工具与脚本（**这一槽会落成泳道的 deps + 落地物**）

**问出口的话术**：

- 「**要装什么？**—— 这条命令要跑起来，一台干净的机器上缺什么？」
- 「**要写什么？**—— harness？fixture 工厂？依赖服务的启停脚本？doctor（缺什么、怎么装）？」

**判据**：

- ✅ **依赖显式、可自查**：每项有**版本** + **安装法**。**doctor 脚本 = 「常见坑」槽的可执行版。**
- ✅ **`MUST NOT` 替操作者装系统依赖**——改用户机器、副作用不可逆。**给命令 + doctor，人自己敲。**
- ✅ **「一台干净的机器」是判据的锚**——不是「我这台机器」。

**反模式**：

> ❌「需要 mosquitto」—— **哪个版本？怎么装？CI 上怎么办？**
> ✅「mosquitto ≥ 2.0（`brew install mosquitto` / CI 用 `eclipse-mosquitto:2` service container）；`hack/broker.sh start|stop` 负责启停；`make doctor` 检查它在不在」

---

### 槽⑥ ⭐ **这层证明了什么 · 看不见什么**

> **这一槽是这个 skill 存在的理由。**
>
> **人最容易忘的，不是「用什么框架」**——那个一搜就有，模型一定会答。
> **人最容易忘的是：「我这层全绿了，可我还是不知道什么？」**

**问出口的话术**（按状态分）：

| 层的状态 | 问什么 |
|---|---|
| **已跑绿** | 「**这层绿了，你依然不知道什么？**」 |
| **`不适用`** | 「**不做这层，你因此看不见什么？**」 |
| **`executor: human`** | 「**人跑一遍能确认什么、确认不了什么？**」 |

**判据（这一槽最容易得到「正确的废话」，逐条防）**：

1. **必须是这个项目特有的一句**，不是通用套话。
   > ❌「单元层不证明集成正确性」—— **正确，但没用。** 这句话对所有项目都成立。
   > ✅「单元层全绿 ≠ 消息真的穿过了 TCP —— 我们的 codec 单测用的是 `bytes.Buffer`，**真实 socket 的分片与粘包它一个都没碰到**」
2. **它必须能指向一个具体的失效**。「看不见什么」= 「**什么样的 bug 会从这层溜过去**」。
3. **⚠️ 最危险的盲区，是「绿的」盲区**——不是「我们没测」，而是「**我们测了，但它什么都没测出来**」。

**⭐ 真实案例（MUST 讲给人听）**：

> mqtt-console 的**残留 session 泄漏探针**：用 `CleanSession=true` 重连，然后断言 `SessionPresent == false`。
> 而 **MQTT 3.1.1 规定：`CleanSession=1` 的 CONNACK **恒**返回 `SessionPresent=0`。**
> ⇒ **这个断言恒真。残留 session 的回归，全部漏过。**
>
> **测试是绿的。断言语句在。数量 > 0。字面上也不恒真（它读了一个变量）。**
> **所有机械层全部失效——只有一个人读代码时问「这个断言真的会红吗？」才抓得到。**
>
> **一份没问过「这层看不见什么」的测试策略，正是这种绿的温床。**

**⇒ 即使模型只答出套话，把这个问题摆在人眼前，本身就已经兑现了「提醒你别忘了考虑」。**
人看见「单元层：不证明集成正确性」这行字，他自己会想起「**那我集成层到底测没测 broker 断连**」。

## 4. `不适用` 怎么答（唯一需要人拍的层状态）

**`不适用` = 这一层我们不做，且我们认这个后果。**

**MUST 带两样**：

| | |
|---|---|
| **理由** | 为什么不做 |
| **⭐ 后果** | **不做这层，我们因此看不见什么** |

> **不写后果，`不适用` 就是一个不需要负责的逃生舱。**
> **写了后果，它才是一个被知情接受的取舍。**

**`不适用` 时，①–④、⑥ 槽豁免**（统一填「不适用，见理由」）——**否则就是逼模型为「不做这件事」编造「怎么实现 / 什么规范 / 什么工具」的废话。机械层会奖励空话、惩罚诚实。**
（`reason` + `consequence` 仍 MUST 有——**那正是 ⑥ 在这个状态下的形态**。）

**合法的 `不适用` 长这样**：

> **e2e：不适用**
> **理由**：本项目是一个 Go 库，没有端到端的部署形态——它没有「用户真的用起来」这个面。
> **后果**：**库的使用者若把 API 用错，我们看不见**——只能靠使用方自己的 e2e。⇒ **补偿措施**：文档里的每个示例都进 `Example` 测试（编译 + 输出断言），至少保证「文档里的用法是真能跑的」。

**不合法的**：

> ❌ **e2e：不适用。理由：暂时没时间。** —— **没有后果。这是逃生舱，不是取舍。**

---

## 5. 层状态：**不问，算出来**

| 层状态 | 从泳道算出 |
|---|---|
| **`不适用`** | 零泳道 + 人写了理由 + 后果 ← **唯一人拍的** |
| `planned` | 有泳道，但全是 `planned` |
| `scaffolded` | 至少一条 `scaffolded`，无 `verified` → 渲染成 **「已搭好，未验证（缺 mosquitto）」** |
| `verified` | 至少一条 `verified` → 渲染成 **「已验证 @ `abc123f` · 2026-07-14」** |

> **MUST NOT 手写层状态。** 它是投影，不是声明——**手写即可伪造、可漂移**。
> **「已实现」这个词 MUST NOT 使用**：它实指「有脚手架」（写了但没验），而用户读到「集成测试：已实现」会以为它跑得起来。**跑不绿是合法状态，跑不绿却装作跑得绿不是。**

## 6. 收尾：**代价必须可见**

**跑完这份清单，MUST 呈现两样：**

1. **`testing-strategy.md` 顶部的代价横幅**（若有待定）：
   ```
   ⚠️ 本框架 12/15 格待定，尚不构成一份可用的测试策略。
      待补：集成层 ①②③④⑥ · e2e 层 ①②③④⑥ · 单元层 ⑥
   ```
2. **收尾报告逐条列出**：所有 `⚠️ 待定` 格 · 所有未 `verified` 泳道 + 其 `blocked_by` · 下一步怎么调用。

> **这个 skill 不会拦你。** 它会把该问的都问一遍，把你没答的**摆在你眼前**，然后让你走。
> **一个不会拦截、但把该问的都问到了的 skill，是合格的。**
> **一个拦得死死的、但没提醒你「你还没想过 e2e」的 skill，是失败的**——哪怕它一个空格子都没放过。
