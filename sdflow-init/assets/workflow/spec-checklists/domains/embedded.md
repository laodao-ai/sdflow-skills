# 领域规则集：嵌入式（RTOS + C）

> `extends: base` —— 本文件只列**嵌入式特有**的设计审查规则；通用质量门禁见
> [`../spec-quality-base.md`](../spec-quality-base.md)。架构与选用规则见 [`../README.md`](../README.md)。
>
> **适用**：任何 RTOS + C 嵌入式 / 固件项目。**不含**具体芯片/SDK 专属约束（堆分配器名、
> 配置结构体宏、构建脚本等）——那些在芯片 delta（如 `embedded-ml307c.md` / `embedded-esp32.md`）里。
>
> 每条规则带触发条件（什么变更要查）。落点：嵌入式领域项绝大多数是 **R（评审判断）**，
> 少数有物证形态可落 **T（模版槽位）**。

---

| ID | 规则 | 触发条件 | 检查点 |
|----|------|---------|--------|
| EMB-01 | **受限回调上下文** | 涉及定时器回调 / ISR / URC 等受限上下文 | 显式声明遵守受限回调约束；说明对应工作线程与消息类型；不在受限上下文直接做 IO / 内存分配 / 日志 / 业务逻辑 |
| EMB-02 | **内存管理策略** | 涉及动态内存分配 | 声明 堆 vs 静态 策略（非关键路径优先静态）；分配失败（NULL）的处理是 WARN 续 / ERROR 止 / fallback，不得"return if NULL"了事；避免初始化后运行路径大量动态分配（碎片） |
| EMB-03 | **任务栈预算** | 新增 RTOS 任务 | 栈大小估算（最深调用链局部变量和 × 安全余量）；栈上无大数组（>256B 移静态/全局）；声明优先级及与现有任务的关系；高优先级任务的 `initialized` 标志在创建线程前置位 |
| EMB-04 | **退避重连** | 任何连接类操作（MQTT/TCP/HTTP/I2C/UART…）的重试 | 明确重试策略，禁裸 `while(retry)` 无限立即重试；指数退避（initial/factor/cap）而非固定间隔；成功路径重置退避；由 RTOS 定时器驱动而非 busy-wait；外部"连接恢复"事件可触发立即重试并重置 |
| EMB-05 | **失败判定阈值** | "N 次失败后触发破坏性操作"的判定 | 复位/重启/状态切换定义 N 阈值，避免首次失败即触发；成功路径说明计数器重置时机；单一信号不可信时要求双信号验证 |
| EMB-06 | **Watchdog 影响** | 新增可能长时间阻塞/占 CPU 的任务或运算 | 识别超过 watchdog 周期的阻塞；长运算有主动 yield 或分批处理；喂狗任务的优先级/频率不受新模块影响 |
| EMB-07 | **错误恢复与降级** | 新增模块 | 模块失败（初始化失败/运行崩溃/通信中断）时系统能否继续；明确完全降级 / 重试恢复 / 触发重启；恢复路径有设计；失败状态对外可观测（心跳/状态上报） |
| EMB-08 | **状态机完整性** | 新模块含多状态（IDLE/RUNNING/ERROR/RECOVERING…） | 枚举所有状态；覆盖所有转换（含边界与异常路径，非仅 happy path）；有 ASCII 状态图或转换表（→ 物证可落 T） |
| EMB-09 | **整数类型设计** | 涉及计数器 / 偏移 / 长度字段 | 类型选择考虑边界（uint8 回绕、中间值溢出）；跨类型边界赋值显式说明；有/无符号混用比较已识别 |
| EMB-10 | **Volatile / 内存可见性** | ISR/受限回调与普通线程共享数据 | 共享数据计划标注 `volatile`；需"写后即可见"时考虑内存屏障；明确单核（一般无需屏障）vs 多核/DMA（需要）场景 |
| EMB-11 | **启动 / 复位路径完整性** | 涉及启动序列 / 复位重启路径 / 安全(降级)模式 / 跨重启状态持久化 | 启动顺序的模块依赖显式（谁必须先 init，呼应 EMB-03 的 `initialized` 时序）；复位/重启不丢关键持久状态，跨 reboot 恢复路径有设计且幂等；重启/降级触发有阈值防风暴（呼应 EMB-05）；安全(降级)模式的进入条件与退出路径明确，状态对外可观测（呼应 EMB-07）；掉电/看门狗复位时机不破坏持久化一致性。本项聚焦"启动与复位"这条正交轴——EMB-05 管"何时触发重启"、EMB-07 管"失败后降级"，本项管"启动/复位本身是否安全完整" |

## 芯片 / 平台 delta 在哪

本层是 RTOS+C 通用维度。具体平台的专属约束（堆分配器 API、配置结构体版本化机制、
构建脚本分类、时间戳降级策略、OTA 槽位等）写在 `extends: embedded` 的芯片 delta 文件，例如：

- `embedded-ml307c.md` —— 蜂窝模组类平台
- `embedded-esp32.md` —— WiFi SoC 类平台

读某芯片完整规则 = `base` + `embedded` + `embedded-<chip>` 三层并集。

*规则集 v1 · extends base · 项目无关*
