# 领域规则集：前端 / UI（通用）

> `extends: base` —— 只列**前端 / 交互**特有的设计审查规则；通用质量门禁见
> [`../spec-quality-base.md`](../spec-quality-base.md)。框架无关（适用于任何有 UI 的产品）。
>
> 读前端完整规则 = `base` + `frontend` 三层并集。

> **机械层前置**：本域推荐 lint/CI 面 = TypeScript strict 模式 + ESLint 通用规则集（未处理 rejected
> promise、未使用变量等）+ Lighthouse CI / 性能预算 CI（CWV 数字回归）；上述工具能确定性抓的不进本清单，
> 仅列语义/设计决策类检查点。

---

| ID | 规则 | 触发条件 | 检查点 |
|----|------|---------|--------|
| FE-01 | **交互边缘场景** | 新增表单 / 提交 / 异步操作 | double-click / 快速重复提交防护；操作中途离开（返回、关闭标签）的处理；慢网络（API 超时 10s 用户看到什么）；并发操作（同一表单两个标签页） |
| FE-02 | **加载 / 空 / 错误态** | 新增数据展示 / 列表 | 加载中、空结果、请求失败三态是否都有 UI 设计，而非只画 happy path |
| FE-03 | **乐观更新与回滚** | 写操作后即时反馈 | 乐观更新失败时的回滚与提示；提交中按钮禁用/loading，防重复触发 |
| FE-04 | **首屏可辨识 + 克制装饰** | 新增/重做落地页/首屏视觉设计 | 首屏在不看 logo 的情况下能否辨认出品牌调性（非通用模板感）；每张卡片/分区是否有存在必要（能删除且不影响信息传达则删）；去掉装饰性元素后界面是否仍显专业/高级（非靠堆砌装饰堆出的"高级感"） |
| FE-05 | **AI-slop 视觉黑名单** | 新增/重做视觉设计 | 是否落入常见"一看就是 AI 生成"的视觉套路：紫色系渐变背景、图标+圆圈+三列卡片布局滥用、全局居中排版、纯装饰性 blob/几何图形、用 emoji 充当设计元素（图标/插画）替代 |
| FE-06 | **CWV 指标锚定** | 涉及新页面/首屏/重交互 | 设计期按 Core Web Vitals 定数字目标：LCP≤2.5s、INP≤200ms、CLS≤0.1（75 分位真实用户）；INP 已取代 FID，勿沿用旧指标 |
| FE-07 | **请求瀑布设计审查** | 新页面/新视图有多个数据依赖 | 画一张"谁等谁"依赖图：render→fetch→render→fetch 串行瀑布是否为设计所致（组件各自 fetch）；能并行/提升/预取的在设计期定 |
| FE-08 | **CSP 与嵌入策略规划** | 新产品面/新站点上线 | 定 strict CSP（nonce/hash）vs allowlist（官方推荐前者）；内联脚本/内联事件处理器架构是否与 CSP 冲突（`onclick=` 会被禁）；是否允许被嵌入（frame-ancestors）；是否规划 report-only 渐进上线路径 |
| FE-09 | **URL 即状态** | 新增筛选/分页/tab/选中态等可交互视图状态 | 筛选/分页/tab/选中态是否进 URL：刷新不丢、可分享、后退符合直觉；深链接可直达；滚动位置恢复策略 |
| FE-10 | **表单设计语义** | 新增/改动表单 | 校验时机分级（格式类 blur 后即时、跨字段 submit）；错误恢复路径（改完即消错）；autocomplete 属性利用（地址/支付自动填充）；不收集不需要的数据；流程摩擦审查（如强制注册才能结账） |
| FE-11 | **错误边界与降级设计** | 新增可能异常的子树 / 引入第三方脚本 | Error Boundary 布点粒度即白屏半径设计（一个组件炸不该白整页）；第三方脚本（统计/客服/广告）失败的降级行为；是否有全局兜底页 |
| FE-12 | **i18n 就绪度** | 多语言目标产品新增文案/布局 | 文案不硬编码；日期/数字/货币用 Intl API 不手拼；翻译文本膨胀 30-50% 的布局余量；复数规则用 `Intl.PluralRules`/ICU 不用单复数二分 |
| FE-13 | **响应式断点策略** | 新页面/布局改动 | 声明断点策略（内容驱动而非设备驱动）；窗口极值（最窄/最宽）布局不破；图片/表格在窄屏的降级形态 |

*规则集 v1 · extends base · 项目无关*
