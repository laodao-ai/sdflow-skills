# memo.md 模板（相位 B 纪要 — 承重结论与拍板决策的增量载体）

用途：memo.md 是相位 B（拷问）期间**唯一**的决策纪要载体（角色对齐 sdflow-spec 的
`decision-memo.md`）。拷问期间每条站稳的承重结论与拍板决策当场追加写入本文件（增量落盘），
不等收敛后一次性落盘。memo.md 属于**历史存档**（决策形成过程的记录，与三件套定稿正文相对），
保持包根落位，MUST NOT 迁移；三件套（`design.md` / `roadmap.md` / `task-log.md`）
MUST NOT 引用本文件任何内容——需要的内容精炼后复制进正式文档正文。

使用方法：
- B 起手三步的第三步——建 `openspec/roadmaps/<name>/` 目录后**立即**把本模板内容 Write 到
  `openspec/roadmaps/<name>/memo.md`（含包名、日期、`状态：DRAFT`），MUST NOT 拖到拷问收敛后才建。
  🔴 **本条字面动作仅适用 create 场景**〔impl-review-fix〕：**continue / replan 场景下既有 memo.md
  已存在时，MUST NOT 用本模板覆盖它**——它承载着此前累积的承重结论 / `## 未决项` / `[确认]` 全局
  写入记录，覆盖即永久丢失。彼时改为**续接追加**并把状态位改回 `状态：DRAFT`，详见 `SKILL.md`
  相位 B「起手三步」第 3 步的分列条款。
- 拷问期间每条站稳（有证据支持或经操作者拍板）的承重结论 / 拍板决策，当场追加写入本文件，
  不预写、不等收敛后批量补记；中断损失窗口 = 两次落盘之间，如实声明，不称零损失。
- 头部状态位写入时机：B 起手写 `状态：DRAFT`；`状态：FINAL`（附定稿日期）**只在**收尾
  checklist 四项**全部**通过之后才写入——MUST NOT 在 B 收敛时提前改写（B 收敛之后还要走
  相位 C 生成与 review 处置，此间中断若已置 FINAL，重入探测——只扫 `状态：DRAFT`——会认不出
  这个半成品包）。`DRAFT` 覆盖「B 拷问中 / C 生成中 / review 待处置」全部未完成态。
