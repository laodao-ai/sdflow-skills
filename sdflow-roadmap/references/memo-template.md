# memo.md 模板（讨论备忘 — 短档考古用）

用途：保留决策形成过程的对话式讨论痕迹。**非三件套成员**（design.md / roadmap.md / task-log.md），不被三件套引用。

**定位**：memo 只承载**短档**讨论——单 session、无跨天/跨压缩场景的讨论备忘，保持包根 `memo.md` 落位不迁。**长档**讨论（跨 session、跨天、经历上下文压缩仍未收敛）改用 wayfinder chart 落盘 `footage/`（map + 票），不靠 memo 硬撑——memo 与 footage 是同一职能（讨论考古层）在不同规模下的两种落盘形态，二选一，不叠加；具体分档判据见 `SKILL.md`「讨论层：三分支路由」。

**是否产出 memo 是可选的**——如果讨论过程有足够多的"对话现场感"、方案矩阵、打分对比值得保留为考古证据，就产出；如果讨论很简单直接得出结论，可以不产出。

**例外：压缩前 flush 场景（此时 memo 转为必需）**〔spec-review-amendment SR-5〕：`/opsx:explore` 起步的讨论若检测到上下文压缩将要/刚刚发生、而 wayfinder map 尚未建立，**SHALL** 立即把当前推理要点 flush 进 memo.md——不追求打磨完整，抢救优先；避免"压缩后才想起留痕、能抢救的已是有损摘要"。flush 后再判定是否需要升级 wayfinder chart；若判定升级，memo 已有内容后续精炼转录进 map 的 Decisions-so-far / 票 Notes。

使用方法：当讨论过程中产生了以下类型的内容时，产出 memo：
- 多个候选方向的详细对比矩阵
- 逐项打分 / 评估的过程
- 被否决方案的完整推演（"当初为啥不用 X" 的长期争议防御）
- 关键假设的修正过程
- 跨多轮对话的讨论演化
- **上下文压缩将/刚发生、且 wayfinder map 尚未建立**（此项触发即必须产出，非可选，见上文"压缩前 flush 场景"）

把本模板内容 Write 到 `openspec/roadmaps/<name>/memo.md`，按实际讨论内容填充。

## 附录 A：为什么保留这份文件

memo 的独特价值在于保留**决策形成过程**的对话语气和考古痕迹：

- 哪些方案被考虑过然后被否决
- 哪些假设在讨论中被修正
- 哪些取舍是在什么语境下做出的
- 哪些直觉/偏好推动了最终方向

这些信息在正式文档（结晶形态）里必然丢失。当未来争议或回顾时（"当初为啥不用 X？"），memo 是唯一能给出答案的地方。

**但**：memo 是草稿，未经打磨。正式文档（`design.md` / `roadmap.md` / `task-log.md`）**不引用** memo（避免"引用了草稿就把草稿当权威源"）。需要的内容应该精炼后复制到正式文档中。

## 附录 B：为什么允许删除 memo

如果未来某次整理觉得 memo 的价值已经完全被 `design.md §决策` 和 `§已决议档案` 吸收（比如 memo 里的方案矩阵已经完整迁移过去了），可以删除 memo。

这个决定应由作者判断，而非自动化。**删除前先检查**：
- memo 里是否还有 design.md 没有的独特内容？
- memo 里的"对话语气"是否有叙事价值（比如将来要写博客复盘）？
- 是否有未来可能重提的被否决方案？

如果三个问题都是"否"，memo 可以删。否则保留。
